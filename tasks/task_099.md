# TASK 099 — UA ART 16-CARD SITE + CRM COMPLETION

## Команда владельца

31.08.2026 владелец подтвердил, что актуальный CRM-реестр содержит 16 карточек,
и потребовал немедленно исправить все ранее невыполненные работы по сайту и CRM.

## Разрешение и порядок

Разрешены изменения production только после последовательности:

`fresh GET-only audit → backup → sandbox → UA-0015 canary → all-16 gate → atomic install → immediate + delayed public verification`.

Любой FAIL запускает rollback. Основные операторские поля, цены закупки, клиентские
данные и media не изменять. Автопубликация дополнительной спецификации запрещена.

## Обязательный результат

- CRM и публичный контур учитывают UA-0001…UA-0016.
- Опубликованные и утверждённые карточки проходят единый publisher без ложного PASS.
- На каждой карточке ровно один постоянный раздел комплексной диагностики.
- Основная информация и «Дополнительная спецификация» разделены; смысловые дубли отсутствуют.
- Дополнительные параметры имеют источник, confidence, категорию, единицу, manual/visibility flags.
- Пустые обязательные разделы показывают корректное состояние ожидания, а не исчезают.
- «На пароме» используется вместо «В море»; stage/counter/category синхронны.
- Киев: CTA «Купить»; остальные этапы: «Задаток 500 $».
- Проверки: mobile 375/390/430 и desktop 1440, immediate и delayed, изображения,
  видимые карточки, отсутствие горизонтального overflow, screenshots.
- UA-0009 получает отдельный утвердительный gate перед финальным PASS.

До полного evidence PASS запрещено объявлять завершение или закрывать issue.
