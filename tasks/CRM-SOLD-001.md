# CRM-SOLD-001 — после «Продано» машина остаётся в каталоге

Владелец, 2026-10-28: «Написал продано в CRM, а машина Audi с каталога не
ушла. Сделай так, чтобы при нажатии „Продано“ машина выходила из каталога
без проблем.»

## Подтверждено пробой CRM-SOLD-PROBE-20261028 (run 40686484969)
- `cars_ui.mark_sold_ok` ставит `status='sold'` и `published=0`, отвечает
  «Из каталога убрана», но каталог сайта не пересобирает.
- «Скрыть» (`toggle_publish`) и «Удалить» (`ua_card_delete`) после записи
  вызывают `publikaciya.obnovit_katalog()` и откатывают CRM при неудаче.
- Фоновый синхронизатор (`ua_crm_public_sync.snapshot`) видит только
  `published=1`, поэтому снятую с публикации машину не замечает.
- Проданная машина — UA-0020 (Audi A6 2016): сегодня в 12:09 по серверу
  `status` → `hidden` (так CRM хранит «sold»), `published` → 0; в
  `video/katalog.html` сервера она осталась. Код `mark_sold_ok` тот же.
- `cars_ui.py` 19adbff3…, `publish_transaction_guard.py` 4b36b2f0….

## План
1. Read-only проба `CRM-SOLD-PROBE-20261028`: текущий код, журнал, статусы
   машин, номера в каталоге сервера.
2. Новый модуль `ua_card_sold.py` (одна ответственность: отметить продажу
   и убрать с сайта через существующий `obnovit_katalog`, при неудаче
   вернуть карточку как была) + замена только обработчика `mark_sold_ok`.
   Пакет `cloud/crm_card_sold_001` (схема пакета «Удалить» crm_card_delete_002).
3. Превью, затем установка через main Actions с бэкапом — после «да»
   владельца. Установка заодно убирает уже проданную Audi из каталога.
