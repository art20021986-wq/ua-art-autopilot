# TASK 090 — CATALOG-DESIGN-STAGE-RESTORE-090 v1.0

## Статус и приоритет

- **CRITICAL / P0 / немедленное восстановление production.**
- Это прямая ограниченная production-команда владельца: «верни сайту дизайн, этапы; найди причину, чтобы больше такого не было; немедленно».
- Дополнительное подтверждение владельца для строго ограниченного восстановления ниже **не требуется**.
- Обязательная схема: BACKUP → READ-ONLY AUDIT → SHADOW → CANARY → ATOMIC PRODUCTION → DELAYED VERIFY.
- Любое несоответствие контракту: STOP + полный автоматический откат.
- Не запускать параллельных production-writer. Использовать общую fair queue / lock.
- Если исполнитель завис или оборвался до production write — автоматически продолжить с последнего безопасного checkpoint. Не повторять уже завершённую запись.

## Наблюдаемый production-дефект

На живом `/video/katalog.html` данные 13 машин сохранены, но утверждённая оболочка каталога уничтожена:

- 13 уникальных кодов UA-0001…UA-0013 присутствуют;
- `nav = 0`;
- `article.catalog-card = 0`;
- фильтры этапов = 0;
- карточки с `data-stage` = 0;
- исчезли прежняя навигация, RU/UA, фильтры «Все / В Киеве / В Грузии / На пароме / В Корее», счётчик «Показано» и утверждённая структура карточек;
- вместо утверждённого каталога опубликована упрощённая bare-shell раскладка с текстом «13 в подборке».

Фактическое распределение опубликованных машин, которое нельзя потерять:

- Все: **13**;
- В Киеве: **3** — UA-0002, UA-0007, UA-0008;
- В Грузии: **1** — UA-0001;
- На пароме: **7** — UA-0005, UA-0006, UA-0009, UA-0010, UA-0011, UA-0012, UA-0013;
- В Корее: **2** — UA-0003, UA-0004.

UA-0012 и UA-0013 должны остаться опубликованными ровно по одному разу, обе на этапе 2 «На пароме».

## Подтверждённая корневая причина

1. Публикационный контур TASK 083 вызывает общий генератор `master_card.obrabotat_obshuyu` / `_ua068_ensure_catalog`.
2. Генератор не ограничился обновлением карточек и счётчиков внутри утверждённой оболочки, а пересобрал весь `katalog.html` из упрощённого шаблона.
3. В одной транзакции упрощённая версия была записана в catalog targets, поэтому машины UA-0012/UA-0013 появились, но утверждённый дизайн и фильтры этапов исчезли.
4. Валидатор TASK 083 проверял количество машин, этап, ссылки и диагностику, но не проверял обязательные DOM-маркеры, структурный fingerprint, фильтры, навигацию и визуальный baseline. Поэтому разрушение дизайна ошибочно прошло как PASS.
5. Последующие публикации способны повторять перезапись, пока источник генерации и проверка оболочки не исправлены.

## Цель

Восстановить **точно прежний утверждённый дизайн каталога и этапы**, сохранив актуальные 13 автомобилей, их фотографии, VIN, цены, ссылки, media counts и текущие статусы. После исправления любая текущая и будущая публикация должна обновлять только данные карточек и счётчики, не меняя защищённую оболочку.

## Источник восстановления — строгий порядок

1. Найти последний production backup `/video/katalog.html` непосредственно **до** публикационной транзакции UA-0012/UA-0013.
2. Сверить его с последним подтверждённым good-state от 2026-08-22: live `/video/katalog.html` совпадал с `/home/Carix/video`, fingerprint-prefix `7948912e56c6dc4c`.
3. Сверить структуру с контрактами TASK 074 / TASK 082 и evidence: `article.catalog-card[data-stage]`, filter chips, i18n, browser-side counter/filter guards.
4. Если точный backup существует — использовать его оболочку. Запрещено заново рисовать дизайн «похожим».
5. В восстановленную оболочку влить актуальные 13 карточек из CRM/published source. Нельзя откатывать данные каталога к 10 машинам.

## Обязательная production-реализация

### A. Backup и preimage

### C. Фундаментальная защита генератора

- Разделить **immutable shell** и **mutable catalog data**.
- Генератору разрешить изменять только:
  - bounded card region;
  - stage counters;
  - «Показано»;
  - timestamp/version.
- Запретить генерацию общего каталога из пустого HTML, bare template или fallback-shell.
- Перед публикацией требовать shell contract markers:
  - nav/menu;
  - RU/UA/i18n;
  - filter controls;
  - `article.catalog-card`;
  - `data-stage`;
  - footer;
  - единый WhatsApp.
- Ввести normalized structural fingerprint: динамические карточные данные и числа исключаются, оболочка обязана совпадать с утверждённым baseline.
- Защитить immutable regions отдельными SHA-256.
- При пропаже хотя бы одного обязательного marker публикация запрещается до записи.
- Не подменять правильный каталог упрощённым fallback. При отсутствии baseline — fail closed.
- Источник данных — только CRM строки `published=1`; draft/unpublished исключены.
- Неизвестный или неожиданный UA-ID блокирует запись.
- Изменение этапа одной машины должно атомарно обновлять:
  - `data-stage` карточки;
  - текст этапа;
  - все filter-chip counters;
  - «Показано»;
  - обе копии каталога.

### D. Транзакция и откат

- Одна блокировка и одна транзакция для:
  - primary card;
  - diagnostics;
  - `/video/katalog.html`;
  - `/site/katalog.html`.
- Запись через temp + fsync + atomic replace.
- При любой ошибке вернуть весь preimage, включая CRM publish state.
- CRM-бот сообщает успех только после полного postcheck; false-success запрещён.

## Тесты — обязательны до production

1. Golden-fixture утверждённой оболочки.
2. 13 текущих машин: exact IDs, no duplicates, exact stage distribution 3/1/7/2.
3. UA-0012 и UA-0013: ровно по одному разу, этап 2.
4. Фильтры: каждый показывает только свой этап и правильное число.
5. Переход одной машины через этапы 1→2→3→4 и обратно без переноса старых полей этапа.
6. Публикация будущей UA-0014: shell fingerprint не меняется, добавляется одна карточка, counters меняются ровно на 1.
7. Draft UA-0014 `published=0`: отсутствует.
8. Idempotency: минимум 10 повторных сборок дают одинаковый normalized hash.
9. Fault injection на каждом write step: полный rollback.
10. Конкурентный запуск: один writer, второй ждёт/завершается без перезаписи.
11. Мобильный Safari 375/390 px и desktop:
    - прежний дизайн визуально восстановлен;
    - фото без чёрных полос;
    - текст не обрезан;
    - фильтры нажимаются;
    - горизонтального overflow нет.
12. Защищённые страницы/карточки вне allowlist не меняются.
