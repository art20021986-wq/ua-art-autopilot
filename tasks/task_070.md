## Факт отказа

При вводе цены `11400` бот ждёт 1–2 минуты и отвечает: `CRM: не читается база crm.db`.
Traceback подтверждает путь:
`cars_ui.catch_message → set_field/remember_price → db.update_card_field/log_action → trace_zhurnal.__exit__ → db.commit → sqlite3.OperationalError: database is locked`.

Установленная причина:
1. `trace_zhurnal.py::_ua_connect` самовольно задаёт `timeout=30.0` и `PRAGMA busy_timeout=30000`.
2. `trace_zhurnal.py::_Obertka.__enter__` повторно повышает любой меньший timeout до 30 секунд.
3. Одна смена цены создаёт несколько последовательных записей: цена, `price_history`, `log_action`; служебная история способна обрушить основной ввод.
4. Старый DB-патч из-за этой обёртки фактически не ограничивает ожидание.

## Исправить

1. Сделать `trace_zhurnal.py` только наблюдателем: запрещено менять SQLite timeout, busy_timeout, journal mode, транзакции и результат commit.
2. Все скалярные изменения карточки (цена, пробег, этап, контейнер, сроки и остальные поля) направить через один writer.
3. Прямой commit ждёт не более 1 секунды. При `locked/busy/queue timeout` запись атомарно уходит в durable FIFO и бот отвечает без traceback.
4. Цена + `price_history` сохраняются одной атомарной операцией. `log_action` неблокирующий: сбой аудита не отменяет основное значение.
5. Удалить/запретить все обходные фоновые writers. Синхронная перестройка сайта и отправка медиа после ввода поля запрещены.
6. Ответ пользователю: текст/число ≤2 с; голос/фото ≤7 с до подтверждения приёма. Ошибка БД в чат не выводится.
7. Правило едино для всех текущих и будущих UA-XXXX. Не создавать новую карточку при редактировании открытой.
8. Существующие карточки, цены, фото, видео, диагностика, контейнеры и сайт не менять.
