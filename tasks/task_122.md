# UA-ART-CRM-CATALOG-FOLDERS-001 v1.0

Дата: 10.09.2026. Основание: прямое поручение владельца разделить «Автомобили» в BOT CRM на «В каталоге» и «Не опубликованные».

Статус: подготовлен локально проверенный модуль представления; интеграция и установка НЕ выполнены. Не считать этот файл командой запуска автопилота. Изменение меню уже запрошено владельцем; повторное утверждение самой идеи не требуется.

## Требуемое поведение

1. «Автомобили» открывает две папки: «В каталоге» и «Не опубликованные» с автоматически рассчитанным количеством.
2. «В каталоге» содержит автомобили, публикация которых успешно завершена и подтверждена действующим каталогом. «Не опубликованные» содержит остальные существующие неопубликованные карточки. Не создавать копии карточек.
3. После успешной публикации карточка появляется в «В каталоге». После успешного снятия с публикации существующим механизмом — в «Не опубликованные». При неудачной операции сохраняется прежнее подтверждённое состояние.
4. Обе папки вместе содержат ровно все карточки прежнего раздела, доступные этому сотруднику; пересечений и пропусков нет. Счётчик равен длине соответствующего полного списка, не текущей страницы.
5. Использовать существующие ID, VIN-подписи, открытие и редактирование карточек. Изменение фото, спецификации или этапа не меняет папку. Пустой список и возврат должны работать; переходы по страницам сохраняют папку.
6. По сообщению владельца сейчас опубликовано 19 автомобилей. Перед установкой сверить точный состав ID; не закреплять число 19 в коде. В этом сеансе число независимо не подтверждено.

## Установленные точки интеграции

- Рабочий модуль на сервере: `/home/Carix/cars_ui.py`.
- Обработчики: `cars_list(update, context)`, `register`, `toggle_publish(update, context)`.
- Признак публикации: `cars.published` (0/1); поле этапа `status` не использовать.
- Существующее открытие: `car_open:<id>`; подпись: `_ua082_vin4_button_label(card)`.
- Источники: `cloud/task_082_vin4_title/task082_exact_patch.py`, `cloud/task_081_publish_repair/patcher_v2.py`, `cloud/task_099_site_crm_repair/evidence/live_audit.json`.

Важное обнаруженное ограничение: обработчик в `patcher_v2.py` устанавливает `published=1` перед выполнением публикации и откатывает его при ошибке. Поэтому передача сырого флага из этой старой версии даст преждевременный переход между папками. Нужен проверенный источник завершённой операции в актуальном процессе; при его отсутствии интеграция остаётся незавершённой. Сам модуль представления эту проблему не исправляет.
