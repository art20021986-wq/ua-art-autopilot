# VIN-KOREA-001 — корейские VIN: поля из лота аукциона

Владелец 2026-11-15 (через координатора, скрин из чата 29): VIN KMHL141EBNA246813 → новая карточка UA-0025 получила
только «Hyundai»; «крайне недоволен», нужно, чтобы почти ничего не вводить руками.

Причина: внутренний корейский VIN (9-й знак не контрольный) — NHTSA vPIC его не знает (ErrorCode 1,5,14,400, год 1992);
защита «только ErrorCode 0» сработала верно.

Решение: новый источник `ua_vin_lots.py` — лот корейского аукциона с ТОЧНО тем же VIN из video/korea/lots.json на
сервере (сборщик korea_auction уже пишет VIN и характеристики). Порядок в `ua_vin_decode.fields`: лот → vPIC для
недостающего. Проверено на живом файле: KMHL141EBNA246813 → Sonata, 2022, 2000, бензин, автомат, 80 000 км.

Ограничение: в lots.json только лоты текущей недели — машина, ушедшая с аукциона раньше, там уже не найдётся.
Предложение (не сделано): копить VIN-индекс прошлых лотов в сборщике.

Пакет: cloud/crm_new_car_vin_003. Дозаполнение новой UA-0025 (Sonata) — отдельная запись в CRM, по «да» владельца.
