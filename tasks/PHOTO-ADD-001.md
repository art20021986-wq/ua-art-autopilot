# PHOTO-ADD-001 — «не могу добрать фотографии» в галереи

Запрос владельца (2026-11-19, через координатора): «Разберись с галереями, я не могу добрать
фотографии. Выяви, в чём проблема, исправь, чтобы в дальнейшем такого не было.»

Проверено координатором: галереи лотов Кореи на сайте целы (40 и 46 фото, все файлы 200).

Подозрения по коду бота (снимок cars_ui.py от 2026-11-01):
1. Фото, застрявшие в очереди приёма (.crm_media_spool.jsonl), считаются в лимит карточки
   (сохранено + в очереди ≥ лимита → «лимит»), а строка с ответом «не принят/не проверен»
   или «card unavailable» из очереди никогда не уходит.
2. Журнал принятых фото (.crm_media_receipts.jsonl) помнит каждое фото навсегда: после
   удаления фото из карточки то же фото повторно не принимается («дубль»).

План:
1. Проба только для чтения PHOTO-ADD-PROBE-20261119 (cloud/photo_add_probe_001): журнал фото
   бота, журнал бота, очередь и журнал принятых фото по карточкам, счётчики фото в CRM и на
   сайте, текущий код приёма фото.
2. Причина + минимальная правка + тест, объяснение владельцу, «да», установка по очереди.

## План исправления (ждёт «да» владельца)
- «Дубль» — только если фото (тот же Telegram unique id) сейчас есть в карточке: журнал хранит file_id
  сохранённого фото; запись журнала считается дублем, только если этот file_id ещё в карточке.
- Тест: принять → удалить → прислать снова = принято; прислать повторно, пока фото в карточке = дубль.
- Установка через автопилот (бэкап, проверка бота, откат) по «твоя очередь» координатора.
