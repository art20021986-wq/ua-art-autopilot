## Постоянный перекрёстный контроль

- Один stage writer под глобальным production lock.
- При реальном переходе очищается payload чужого этапа.
- SQLite triggers страхуют legacy/direct SQL.
- Public projection скрывает payload чужого этапа.
- Primary, diagnostic, /video/katalog.html и /site/katalog.html публикуются
  синхронно из одного CRM snapshot с atomic replace и byte read-back.
- Success только после CRM → карточка → оба каталога → категории → chips.
- Повтор идемпотентен; дублей и дрейфа счётчиков нет.
- Любой сбой: compensating DB rollback, точное восстановление файлов,
  auto-rollback и restart единственного `python3.10 /home/Carix/start_safe.py`.
- Один последовательный автоматический повтор разрешён; параллельный writer
  запрещён. Runtime LLM tokens = 0.
