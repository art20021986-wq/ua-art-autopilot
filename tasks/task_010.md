## Owner directive — highest priority

The owner defines the permanent operating model for UA ART AUTOPILOT:

- ChatGPT/Codex = ideas, architecture, task specification, orchestration, audit. It must not substitute its own working deliverables for Claude deliverables.
- Claude = the only author of owner-facing technical working files, through the Anthropic API worker and durable GitHub `cloud/` provenance.
- PythonAnywhere = execution environment.
- NOTHING generated by Claude may be executed, installed into an active production path, imported by production, reloaded, or published on PythonAnywhere until the owner has manually approved that exact release candidate.
- Owner approval must be bound to an exact TASK_ID + manifest SHA-256 + file SHA-256 list. A generic `APPROVE` is never enough.
- Approval is one-time and cannot authorize later modified bytes.
- Automatic transfer to a quarantine/inbox is allowed before approval; execution/install into active paths is forbidden before approval.
- Production publication/change must remain a separate CRITICAL approval after tests and visual review. One approval must never implicitly authorize production.

The target owner experience is:

1. ChatGPT/Codex formulates the task.
2. Claude authors/reviews the files and returns a release candidate under `cloud/`.
3. System automatically prepares a cryptographic release manifest and safely transfers candidate files to PythonAnywhere quarantine/inbox only.
4. Claude/owner-facing status says exactly what will run, where, hashes, risk, and whether it is sandbox-only or production-capable.
5. Owner manually approves the exact candidate.
6. Only after that approval, the trusted PythonAnywhere gate automatically verifies provenance/hash/allowlist/backups and runs or installs only the approved bytes/action.
7. A machine receipt proves exactly what happened.
8. Any production write/publication requires a second explicit CRITICAL approval.

Required conceptual tools:

- `approve_release(task_id, manifest_sha256, owner_confirmation)` — writes one-time approval only for the exact current manifest.
- `reject_release(task_id, manifest_sha256, reason)` — marks rejection only.

`approve_release` must NOT accept a shell command, target path, file bytes, URL, Python code, or free-form deployment payload from Claude Chat. Those must come exclusively from the Claude-authored immutable manifest already stored by the system.

## Mandatory two-gate model

### GATE A — PYTHON EXECUTION / SAFE INSTALL APPROVAL

Required for ANY execution of a newly Claude-authored executable/script on PythonAnywhere, even if read-only/sandbox.

Owner phrase semantics must bind to exact candidate, e.g.:
`APPROVE_RUN TASK_010 MANIFEST_SHA256=<64hex>`

After Gate A, allowed action is only the manifest-declared SAFE/SANDBOX operation under explicit allowlists.

### GATE B — CRITICAL PRODUCTION APPROVAL

Required separately for:
- production publication;
- live site overwrite;
- CRM write/schema change;
- WSGI/reload/restart;
- deletion;
- mass regeneration;
- shared generator change;
- moving staged files into live paths;
- any multi-card production change.

Owner phrase semantics must bind to exact validated production release manifest, e.g.:
`APPROVE_PRODUCTION TASK_010 MANIFEST_SHA256=<64hex>`

Gate A can NEVER satisfy Gate B.
