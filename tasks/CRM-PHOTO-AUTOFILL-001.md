# CRM-PHOTO-AUTOFILL-001 — фото с VIN → новая карточка CRM

## Запрос владельца (2026-11-01)
Фото/скриншот в бот CRM должно само создавать новую карточку и заполнять все видимые поля.
Скриншот AUTO.RIA (Mercedes W245, VIN WDD2452322J660244) получил «Поля CRM не распознаны».

## Утверждённые правила (ответы владельца в чате)
1. VIN виден и его нет в CRM → создать карточку, заполнить все распознанные поля CRM.
2. VIN уже есть в CRM → «Карточка с таким VIN-кодом уже существует», новую не создавать.
3. VIN не виден → карточку не создавать.
4. На сайте автоматически не публиковать («нет»).
5. Марку заполнять по VIN, если она определяется однозначно («да»).

## Причина (проба CRM-PHOTO-PROBE-20261101-R2, cloud/crm_photo_autofill_001)
Сервер: Tesseract 4.1.1, нагрузка ~2.5 на 4 CPU. Проход распознавания длится 0.3–5.7 с,
а local_ocr обрывал каждый через 1.45 с; полный проход шёл в режиме «разрозненный текст»
(psm 11) и VIN не видел. VIN находил только последний проход (3.35 с) — всегда обрывался.
Итог на сервере: 11.7 с, VIN не найден. Плюс AUTO.RIA ставит значение строкой ниже подписи —
текущие разборщики этого не понимают (цвет, состояние терялись).

## Решение (cloud/crm_photo_card_001)
- local_ocr.py — 2 строки: полный проход psm 4 (одна колонка), проход может использовать весь
  оставшийся бюджет фото (без 1.45 с).
- screen_fields.py (новый) — «подпись ⏎ значение» → «подпись: значение» для существующих разборщиков.
- vin_brand.py (новый) — марка по первым 3 символам VIN (WMI, ISO 3780), только однозначные коды.
- photo_card.py (новый) — правила 1–4; запись через существующий ai_filter.store (publish=False).
- team_bot.py — ветка фото в run_ai_draft передаёт фото в photo_card.handle.
Без новых библиотек. Текст, голос и остальной бот не меняются.

## Статус
Код и тесты готовы; предпросмотр на сервере → затем установка только после «да» владельца.
