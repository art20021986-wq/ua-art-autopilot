# UA-ART-CRM-ONECLICK-PUBLISH-001 · v1.0

Критическое ТЗ: публикация объявления одним нажатием и удаление лишних разделов CRM.
Заказчик: Артём, UA ART. Дата: 27 сентября 2026 года.

**Статус: код подготовлен и локально проверен; в рабочую CRM не установлен.
Исправление на живом сайте и публикация UA-0021 этим заданием пока не подтверждены.**
Поручение владельца включает исправление; повторного общего утверждения не требуется.

## 1. Требуемое поведение

1. Убрать «Уже в каталоге · скрыть» из экрана объявления.
2. Убрать «Как видит покупатель» из создаваемых экранов карточки и объявления.
3. «Разместить объявление» одним нажатием запускает публикацию непосредственно на сайт.
   Не открывать вместо этого длинный рекламный текст и второй шаг публикации.
4. Одинаковый путь действует для черновика, повторной публикации и карточки, у которой
   флаг published=1 установлен, но публичная публикация не завершилась.
5. Повторное нажатие не скрывает автомобиль, не создаёт новый ID и не сбрасывает
   задержку автоматического повтора. Действие «Скрыть от клиентов» остаётся отдельным.
6. Старые неоднозначные кнопки car_pub и старый предпросмотр сообщают, что нужно
   открыть карточку заново; они не публикуют и не скрывают автомобиль.
   Удалить кнопки из ранее отправленных Telegram-сообщений без известных message_id
   нельзя; новый код меняет будущие экраны и безопасно обрабатывает старые нажатия.

## 2. Подтверждённые причины

| Причина | Основание | Исправление |
|---|---|---|
| Флаг CRM ошибочно определяет сценарий кнопки | ad_screen вызывает публикацию лишь для published=0; для published=1 показывает текст и «Уже в каталоге · скрыть» | Единое явное действие публикации независимо от флага |
| Флаг CRM не доказывает доступность объявления | По текущему checkpoint UA-0021 имеет published=1, но отсутствует в каталоге | Принудительный запрос обработчику и проверка публичной страницы |
| Разные наборы автомобилей при сборке и проверке | _ua9_sobrat_katalog возвращает архивные записи, строгая проверка ожидает активные; CATALOG_ROW_SET_MISMATCH | Единый список активных опубликованных автомобилей; проверку и откат сохранить |
| Долгая операция удерживает обработку CRM | Старый callback ожидает полную публикацию; параллельно работает фоновый publisher | Callback запускает задачу, публикацией занимается существующий единственный worker |
| Возможен текст ошибки без завершения операции | Старый обработчик откатывает флаг и заканчивается сообщением | Долговечный запрос, автоматические повторы и отдельное подтверждение результата |

Скриншот подтверждает интерфейс, но не содержит исключения публикации.
Ошибки каталога установлены по коду и уже сохранённым диагностическим материалам проекта.

## 3. Контракт публикации

Проверить сотрудника CRM, существование карточки, обязательные поля и действующий этап.
Ошибки заполнения показать понятным текстом. На ошибочных данных публикацию не запускать.

Для черновика использовать штатный журналируемый API CRM для установки намерения
published=1. Не менять статус, цены, VIN, фото, видео и прочие поля. Сохранить запрос
с идентификатором, ревизией и адресом сообщения об операции. Подтверждать запуск
только после сохранения запроса; сообщение об успешной публикации отделить от запуска.

Существующий worker использует прежнюю блокировку, сборщик, резервирование,
проверку пакета, откат и публичную проверку. Явный запрос не должен пропускаться
из-за совпадения с установочным baseline. Если данные меняются при сборке,
доработать актуальную ревизию; старое подтверждение не засчитывать.

При временной ошибке сохранять запрос и повторять с ограничением частоты.
Использовать действующий контроль повторов пакета crm_performance_001.
Одна ошибка не должна бесконечно нагружать сервер и блокировать прочие карточки.
Для удалённой, скрытой или архивной карточки отменить ожидающий запрос.

Сообщение «✅ Объявление опубликовано на сайте» допустимо только после проверки
обычного публичного URL и соответствия актуальной ревизии CRM. В нём — ссылка
на карточку и возврат в CRM. Отправлять подтверждение в исходный диалог операции.
При сбое Telegram сохранить подтверждение для повторной доставки после перезапуска.

«Сразу» означает запуск с одного нажатия, без второго решения оператора.
Мгновенный сетевой результат не гарантируется. При штатных ресурсах проверить
быстрый ответ бота и достижение публичного результата; целевой срок — до 60 секунд
для заполненной карточки с уже загруженными материалами. Пока он не измерен.

## 4. Реализация кандидата

Общий сборщик: cloud/crm_oneclick_publish_001/build_candidate.py.
Он последовательно использует уже подготовленные stage_edit_recovery_001 и
crm_performance_001, затем добавляет данный сценарий.

| Итоговый файл | Изменение |
|---|---|
| cars_ui.py | Удаление двух элементов, одно нажатие, обработка старых кнопок, доставка подтверждений |
| publikaciya.py | Согласованный список активных автомобилей из stage recovery |
| ua_crm_public_sync.py | Обработка явных запросов, сохранение прежних повторов и проверок |
| ua_publish_requests.py | Малый журнал запросов и недоставленных подтверждений на стандартной SQLite |

Журнал находится в закрытой папке .crm_publish_requests (0700).
Он содержит служебные chat_id/message_id; его нельзя сохранять в публичном GitHub.
Полные серверные исходники и CRM-данные также не включены в пакет.
Сборщик проверяет точные исходные SHA и компилирует результат, но ничего не устанавливает.

## 5. Проверки и приёмка

Локально проходят 68 проверок: 28 нового сценария, 15 производительности,
18 восстановления этапов и 7 политики статусов. Сборка четырёх файлов компилируется.
Проверены дубли нажатий, устойчивость журнала, устаревшее подтверждение, новая правка
при публикации, сохранение повторов, ошибка публичного URL, удаление/архив,
недоступность Telegram, отсутствие прав и незаполненные данные.

Это изолированные проверки с заменой внешних эффектов; они не доказывают установку,
скорость настоящего бота или исправление сайта. Полная серверная репетиция,
согласованный резерв/откат, Gate B, проверка Telegram и браузеров ещё не выполнены.

Условия окончательной приёмки:

- Новые экраны рабочего бота не содержат двух удалённых элементов.
- Одно нажатие размещает заполненную карточку; повтор не скрывает её.
- UA-0021 присутствует в актуальном каталоге и открывается по обычному URL;
  поля соответствуют актуальной CRM, счётчики пересчитаны из фактического набора.
- Временный сбой и перезапуск не теряют принятую операцию.
- Нет ложного успеха, дубликатов и перезаписи более новых правок.
- Сообщение об успехе доставляется после проверки сайта; проверены Safari/Chrome
  и используемый встроенный браузер. Зафиксированы фактические сроки.
- Указаны версия установленных файлов, резерв и результат проверки отката.

## 6. Текущее препятствие и порядок установки

Свежий Dashboard PythonAnywhere в этой работе: «You are in the tarpit»,
8716,57 из 5000 CPU-секунд. Это исчерпание суточной квоты, не мгновенная загрузка CPU.
Панель показывала около 3 ч 4 мин до сброса. По правилу CLAUDE.md при ≥85%
тяжёлые операции откладываются. Перед продолжением необходим новый замер.

В репозитории действует EMERGENCY_HALT после запуска 36268504600.
Транзакция tx-36268504600-54c3be3cfc4dd0da осталась ROLLING_BACK;
автоматический откат был зарезервирован, но не выполнен из-за отсутствия
ledger-bound nonce в checkout восстановления.

1. Завершить зарегистрированное восстановление этой транзакции с сохранением истории.
   Не удалять HALT вручную, не подменять nonce и не использовать чужой маршрут TASK120.
2. Проверить ресурсы и свежие SHA сервера. Повторно не запрашивать общее разрешение владельца.
3. Согласовать один конечный пакет с незавершённым исправлением медиа из PR128.
   Не устанавливать несколько перекрывающих друг друга cars_ui/worker.
4. Испытать резервирование, установку и откат, включая новый журнал запросов.
   Существующие задания и более новые правки владельца при откате не терять.
5. Пройти Gate B и выполнить установку штатным GitHub Actions из main.
6. Перезапустить только подтверждённую службу CRM, проверить загруженную версию,
   публикацию UA-0021 и приведённые критерии приёмки.

Публикация ТЗ или кода в GitHub не является установкой на PythonAnywhere.
Новая автоматическая отложенная установка в этой работе не настраивалась.
