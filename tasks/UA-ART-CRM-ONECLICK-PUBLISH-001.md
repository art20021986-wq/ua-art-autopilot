Критическое ТЗ: публикация объявления одним нажатием и удаление лишних разделов CRM.
Заказчик: Артём, UA ART. Дата: 27 сентября 2026 года.

**Статус: установлено в рабочую CRM. GitHub Actions 36301475826 — SUCCESS;
транзакция закрыта FINISHED 27.09.2026 в 07:13 UTC. Точные SHA четырёх файлов
проверены, бот перезапущен и работает. UA-0021 опубликован штатным обработчиком.
Сквозное нажатие в Telegram и скорость при нормальной квоте отдельно не измерены.**
Поручение владельца включает исправление; повторного общего утверждения не требуется.

## 1. Требуемое поведение

1. Убрать «Уже в каталоге · скрыть» из экрана объявления.
2. Убрать «Как видит покупатель» из создаваемых экранов карточки и объявления.
3. «Разместить объявление» одним нажатием запускает публикацию непосредственно на сайт.
   Не открывать вместо этого длинный рекламный текст и второй шаг публикации.
4. Одинаковый путь действует для черновика, повторной публикации и карточки, у которой
   флаг published=1 установлен, но публичная публикация не завершилась.
5. Повторное нажатие не скрывает автомобиль, не создаёт новый ID и не сбрасывает
   задержку автоматического повтора. Действие «Скрыть от клиентов» остаётся отдельным.
6. Старые неоднозначные кнопки car_pub и старый предпросмотр сообщают, что нужно
   открыть карточку заново; они не публикуют и не скрывают автомобиль.
   Удалить кнопки из ранее отправленных Telegram-сообщений без известных message_id
   нельзя; новый код меняет будущие экраны и безопасно обрабатывает старые нажатия.

## 3. Контракт публикации

Проверить сотрудника CRM, существование карточки, обязательные поля и действующий этап.
Ошибки заполнения показать понятным текстом. На ошибочных данных публикацию не запускать.

Для черновика использовать штатный журналируемый API CRM для установки намерения
published=1. Не менять статус, цены, VIN, фото, видео и прочие поля. Сохранить запрос
с идентификатором, ревизией и адресом сообщения об операции. Подтверждать запуск
только после сохранения запроса; сообщение об успешной публикации отделить от запуска.

Существующий worker использует прежнюю блокировку, сборщик, резервирование,
проверку пакета, откат и публичную проверку. Явный запрос не должен пропускаться
из-за совпадения с установочным baseline. Если данные меняются при сборке,
доработать актуальную ревизию; старое подтверждение не засчитывать.

При временной ошибке сохранять запрос и повторять с ограничением частоты.
Использовать действующий контроль повторов пакета crm_performance_001.
Одна ошибка не должна бесконечно нагружать сервер и блокировать прочие карточки.
Для удалённой, скрытой или архивной карточки отменить ожидающий запрос.

Сообщение «✅ Объявление опубликовано на сайте» допустимо только после проверки
обычного публичного URL и соответствия актуальной ревизии CRM. В нём — ссылка
на карточку и возврат в CRM. Отправлять подтверждение в исходный диалог операции.
При сбое Telegram сохранить подтверждение для повторной доставки после перезапуска.

«Сразу» означает запуск с одного нажатия, без второго решения оператора.
Мгновенный сетевой результат не гарантируется. При штатных ресурсах проверить
быстрый ответ бота и достижение публичного результата; целевой срок — до 60 секунд
для заполненной карточки с уже загруженными материалами. Пока он не измерен.

## 4. Реализация

Общий сборщик: cloud/crm_oneclick_publish_001/build_candidate.py.
Он последовательно использует уже подготовленные stage_edit_recovery_001 и
crm_performance_001, затем добавляет данный сценарий.

| Итоговый файл | Изменение |
|---|---|
| cars_ui.py | Удаление двух элементов, одно нажатие, обработка старых кнопок, доставка подтверждений |
| publikaciya.py | Согласованный список активных автомобилей из stage recovery |
| ua_crm_public_sync.py | Обработка явных запросов, сохранение прежних повторов и проверок |
| ua_publish_requests.py | Малый журнал запросов и недоставленных подтверждений на стандартной SQLite |

Журнал находится в закрытой папке .crm_publish_requests (0700).
Он содержит служебные chat_id/message_id; его нельзя сохранять в публичном GitHub.
Полные серверные исходники и CRM-данные также не включены в пакет.
Сборщик проверяет точные исходные SHA и компилирует результат. Установка выполняется
отдельным пакетом cloud/crm_oneclick_release_001 через GitHub Actions из main.

Сообщение «Codex could not read the local image … IMG_9391.jpeg: No such file or
directory» относится к отсутствующему локальному файлу вложения, а не к обработчику

вложений Codex этим обновлением не выполнялось.

существования файла. При доступном вложении работать с ним непосредственно; при
наличии идентификатора файла получить новую локальную копию. Если изображение нигде
не доступно, запросить повторное вложение и не объявлять его просмотренным.
