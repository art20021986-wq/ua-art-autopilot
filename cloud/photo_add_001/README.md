# PHOTO-ADD-001 — удалённое фото можно прислать в карточку снова

Задача: `tasks/PHOTO-ADD-001.md`. Владелец 19.11: «не могу добрать фотографии».

Причина (пробы PHOTO-ADD-PROBE-20261119, -R2): журнал принятых фото CRM-бота (`.crm_media_receipts.jsonl`)
помнит каждое фото карточки навсегда; после «Удалить фото» то же фото, присланное снова, бот отбрасывал как «дубль».

- `crm_online_guard.py` (`edit_crm_online_guard.py`): журнал хранит, какое фото (file id) сохранила каждая запись;
  `media_saved_file(key)`; `media_mark(..., file_id)` пишет новую запись, если фото сохранено заново.
- `cars_ui.py` (`edit_cars_ui.py`): «дубль», только если сохранённое фото сейчас есть в карточке; очередь передаёт
  file id в журнал. Остальное без изменений.
- Тесты: `test_photo_add.py` — живой код приёма фото (выдержки в `fixtures/`): ошибка воспроизводится до правки,
  после — «принять → удалить все → прислать снова» = принято; повтор, пока фото в карточке, = дубль.
- Превью: компиляция обоих файлов в python3.10, журнал-кандидат во временной папке, чтение живого журнала
  (только подсчёт). Установка — как crm_bot_profile_001 (бэкап, пауза бота, замки, откат).
- Начало сбоя (проба R3): в «Добавить фото» UA-0011 попало видео (02:07 UTC) и сохранилось среди фото; одно видео в
  фото ломает альбом галереи бота (показываются только первые 5 фото). Правка `cars_ui.py` (catch_message): в раздел фото
  принимаются только фотографии; видео/файл — прежний ответ бота «В этот раздел нужен другой тип файла…», не сохраняется.
