# Owner policy candidate — NOT INTEGRATED / NOT DEPLOYED

Статус: локальный кандидат в отдельный пакет. Автопилот, Telegram, CRM и сайт
этот код не вызывают. Runtime manifest, workflows и production не изменены.

Дополнение по ответу владельца: `price_captions.py` задаёт проверенные RU/UA
подписи — Украина с доставкой до Киева, растаможкой и сертификацией в Украине; Грузия с доставкой до авторынка
AUTOPAPA, паркинг №16, без растаможки в Грузии. Модуль не меняет суммы и не
подключён к рабочему генератору. Доставка за пределы указанных мест, оплата и срок
хранения/парковки и отсутствие иных доплат этим ответом не подтверждены.

## Зафиксированные правила владельца

- Любой сбой: STOP и событие FAILURE; немедленных автоматических повторов нет.
- Возобновление — только после устранения причины и свежих успешных проверок,
  для той же задачи/request/попытки и следующего доказанно не начатого действия.
  Завершённые действия не повторяются; неопределённый результат записи требует
  reconciliation, не повторной записи. Терминальные задачи не возобновляются.
- Для production дополнительно нужны проверенные backup, rollback, существующий
  Gate B receipt и разрешение владельца. Модуль их не создаёт и не подтверждает.
- Независимая работа допустима только при свежем доказательстве изоляции,
  непересекающихся канонических ресурсах и точных проверенных FINISHED receipts
  зависимостей. Общие control-plane/global scopes консервативно блокируют работу.
- Telegram: только ошибки и ежедневный краткий отчёт со ссылкой на подробный,
  лично владельцу в CRM-бот. Время отчёта — 10:00 Asia/Ho_Chi_Minh; работа — 24/7.
- После первого подтверждённого уведомления о конкретном сбое отдельных повторных
  напоминаний нет: нерешённый сбой включается в ежедневный отчёт. Новый отдельный
  сбой требует немедленного сообщения. Первое сообщение, ещё не доставленное,
  остаётся ожидающим доставки и не отбрасывается как повторное напоминание.
  Проверки продолжают работать круглосуточно; политика ограничивает сообщения.
- Владелец отклонил резервную почту: единственный канал уведомлений автопилота —
  Telegram; резервных каналов нет. При недоступности Telegram уведомление должно
  оставаться в надёжной очереди до подтверждённой доставки в тот же личный чат.
  Этот пакет задаёт политику; очередь и отправитель ещё не подключены.
  Восстановление доставки уведомлений не разрешает повтор production-действия.
- Ответ владельца о задержке запуска: обычная согласованная и готовая задача
  должна дать уведомление о сбое запуска при ожидании **300 секунд и более**.
  `START_DELAY` — подтип сбоя, не сообщение о ходе работы. Один readiness-эпизод
  получает один ключ уведомления; новый опрос не должен сбрасывать таймер.
  Обновление цены сохраняет отдельный срок **60 секунд**, известные ошибки
  по-прежнему требуют немедленной реакции, а не ожидания пяти минут.

## Контракт и ограничения

`price_publication.py` добавляет проверку права подтвердить публикацию: совпадают
автомобиль, сохранённая версия и обе цены USD в CRM, публичной карточке и каталоге;
содержимое проверено, остальные данные сохранены. HTTP 200 без сверки не считается
успехом. Другая версия CRM требует сверки без повтора старой записи, расхождение
публичной цены останавливает задачу, поздняя публикация отмечается как нарушение
срока 60 секунд. При сбое выбирается сохранение введённой цены в CRM — это безопасное
решение исполнителя после ответа «Давай без ошибок», а не выбранный владельцем пункт.
Модуль ничего не публикует и не подключён к боту. Доверенный адаптер должен получить
реальные доказательства, удерживать блокировку записи и повторно проверить текущую
версию CRM перед подтверждением. Повторная публикация требует прежних recovery gates.

`failure_decision`, `resume_decision`, `independent_task_decision` и
`telegram_event_selected` — чистые функции. Результат `*_ELIGIBLE` означает
только соответствие переданным фактам, **не выполненную операцию**. Все обязательные
факты передаются явно: нет переключателя, включающего auto-resume по умолчанию.
Булевы поля принимают только `bool`, не 1/0/строки; обязательны непустые identity,
SHA-256 bindings и timestamps с часовым поясом. Некорректные входы вызывают
`PolicyInputError`; будущая интеграция обязана считать это STOP/WAIT, не обходить.

Свежесть ограничена пятью минутами — консервативная граница этого кандидата,
не доказательство свежести live-проверок. Хеши — только ссылки на доказательства:
независимый доверенный адаптер должен проверить реальные байты, timestamp,
соответствие identity и источники. Кандидат не проверяет подлинность сам.

`start_delay_decision` также является чистой функцией: выбирает уведомление,
не запускает задачу, не ставит таймер и ничего не отправляет. Текущее состояние
очереди должно быть подтверждено не более 30 секунд назад; сама готовность может
быть значительно старше пяти минут. Адаптер должен сохранять readiness-эпизод
и момент готовности, повторно проверить состояние перед отправкой, исключить
параллельную отправку и надёжно записать подтверждение доставки. Ошибка доставки
не равна успешному уведомлению. Эти интеграционные механизмы ещё не установлены.

Отсутствуют: сетевые вызовы, запись файлов, секреты, scheduler, Telegram sender,
разрешение получателя, доставка/дедупликация уведомлений, автоматическое снятие
HALT, dispatch, восстановление, locks и атомарные транзакции. Канонические resource
scopes должен предоставлять проверенный адаптер; перечисление ресурсов по одному
текстовому названию не доказывает независимость.

## Локальная проверка

Из каталога пакета:

```sh
python -B -m unittest -v test_owner_policy.py
```

Полный набор из корня ветки:

```sh
python -B -m unittest discover -s cloud/task088_autopilot_owner_policy -p 'test_*.py' -q
```

До подключения обязательны отдельная ревизия, живые интеграционные проверки,
устранение 7 существующих FAIL workflow-контрактов, проверка runtime registration
и Gate B. Обходить защиту или править manifest ради зелёных тестов запрещено.
