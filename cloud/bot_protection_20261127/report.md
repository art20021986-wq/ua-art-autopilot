# BOT-PROTECT-001 — разведка и план (сессия 43, 27.11.2026; только чтение)

Ничего на сайте, в CRM и в Google не менялось. Источники: код и отчёты репозитория, официальная справка Google,
PythonAnywhere и Cloudflare (ссылки внизу). Живой сайт из облака не открывается (сеть контейнера), поэтому факты о
сервере — из прошлых проверок автопилота (ссылки на них указаны).

## 1. Реклама Google — кто платит за «клики конкурентов»
- Сейчас: 1 кампания, только поиск Google (сети партнёров и КМС выключены), показ только людям, которые находятся
  в Украине (PRESENCE). С запуска 15 кликов, 307 грн (ADS-CHECK-20261127-R1). Это самые «чистые» настройки:
  больше всего накруток бывает в КМС и у сайтов-партнёров, они у нас выключены.
- Google сам отсекает недействительные клики (повторные, роботы, накрутка): пойманные до счёта — не списываются и в
  отчёт не попадают; пойманные позже — возвращаются кредитом «Invalid activity» в разделе оплаты (не деньгами на
  карту). Можно подать запрос на проверку кликов за последние 60 дней.
- Видно ли у нас: столбцы «Недействительные клики» и «Доля недействительных кликов» есть в отчётах (и в API:
  metrics.invalid_clicks, metrics.invalid_click_rate на уровне кампании). Наша проверка рекламы (сессия 37) их пока
  не читает — добавить 1 строку в её ежедневную сводку (только чтение).
- Исключение IP: до 500 адресов на кампанию (и общий список аккаунта). Google не показывает IP кликнувших, поэтому
  это имеет смысл только если в журнале сайта видно один и тот же адрес с меткой рекламы (gclid) много раз. Сейчас
  поводов нет — держать как ответ на конкретный случай, а не заранее.

## 2. Сайт — что видит сервер и что можно сделать без внешних сервисов
- Важно: страницы сайта (/video/…) отдаёт PythonAnywhere напрямую как файлы (статическая привязка /video/), минуя
  наш код. Значит «вышибала» в нашем коде их не видит и не может отсечь робота, читающего страницы. Убрать привязку
  нельзя: сайт станет медленнее и будет тратить лимит процессора.
- Через наш код проходят: отметки счётчика (/ua/a/e), robots.txt, sitemap, отправка заявок/форм. Здесь защита
  возможна и полезна: ограничение частоты с одного адреса (адрес берём из X-Real-IP, как советует PythonAnywhere),
  отказ явным роботам по подписи браузера. Своей блокировки IP/брандмауэра у PythonAnywhere нет — по их же совету
  это делается в приложении.
- Чем роботы-читатели вредят реально: денег не тратят (реклама платит только за клик, сайт — за файлы не платит),
  лимит процессора не тратят (файлы отдаёт сервер). Вред — только грязная статистика; её закрываем в счётчике (п.3).
- robots.txt: сейчас «всем можно, кроме /video/preview/» — правильно для продвижения. Защитой он не является: плохие
  роботы его не читают. Менять не нужно. AdsBot (проверка рекламы) и Googlebot не трогаем.
- Если ограничивать частоту, то ответом 429 и только для не-Google: Google понимает 429/503 как «сервер перегружен»
  и при долгом применении урежет обход и даже приостановит рекламу. Googlebot проверяется по двойной проверке DNS
  или опубликованному списку адресов Google — подпись браузера подделать легко.

## 3. Счётчик и «Посетители из Украины» — засоряется ли ботами
- Свой счётчик пишет только браузеры, выполнившие скрипт: честные роботы (Googlebot, ChatGPT и др., 3–4 тыс.
  запросов в день) в нём не появляются. Отчёт «Из Украины» дополнительно берёт только часовой пояс Europe/Kyiv —
  роботы дата-центров отпадают.
- Дыра: «браузер-робот» (управляемый Chrome) с поясом Киева посчитается как человек. Признак такого браузера
  (navigator.webdriver) счётчик сейчас не проверяет; сервер не проверяет подпись и частоту отметок.
- GA4 сам исключает известных роботов (отключить нельзя), остальных — только фильтром по условию.

## 5. Cloudflare (BOT-CF-001) — план подключения (владелец 27.11: «включаю … активирую сразу»)
Бесплатный тариф Cloudflare. Что важно для нашего сайта (сверено: справка PythonAnywhere «Using Cloudflare», Cloudflare docs):
- Cloudflare начинает работать, когда у регистратора (rehost.com.ua) меняют 2 адреса DNS-серверов на адреса Cloudflare.
  Все записи домена (сайт www → PythonAnywhere, адрес без www, почта, проверки Google) должны быть перенесены 1:1 —
  проверяем автопилотом до смены, иначе может пропасть сайт или почта.
- Автопродление сертификата HTTPS от PythonAnywhere (Let's Encrypt) за Cloudflare не работает. Правильно: выпустить
  сертификат Cloudflare для сервера (15 лет) и поставить его на сайт PythonAnywhere; режим шифрования «Full (strict)».
- «Bot Fight Mode» на бесплатном тарифе НЕ включаем: его нельзя настроить исключениями, он может мешать проверкам
  автопилота и проверкам Google. «Блокировать ИИ-ботов» не включаем (сайт показывается в поиске ChatGPT).
- Включаем: прокси (настоящий адрес сервера скрыт), 1 бесплатное правило частоты на /ua/a/e и /api/, кэш — выключен
  (иначе после установок могут показываться старые файлы). «Режим атаки» (Under Attack) — аварийная кнопка, только
  при реальной атаке, автопилот может включить/выключить по команде владельца.
- После включения прокси адрес посетителя приходит в заголовке Cloudflare: ua_bot_guard и ограничения форм надо
  перевести на него (отдельная маленькая правка, входит в BOT-CF-001), иначе все посетители будут «с одного адреса».

Шаги владельца (его аккаунты — сделать за него нельзя):
1. dash.cloudflare.com → регистрация → «Add a domain» → uaart.com.ua → тариф Free → дождаться списка записей. Адреса
   DNS-серверов у rehost пока НЕ менять.
2. Профиль → API Tokens → Create Token → шаблон «Edit zone DNS» + права Zone Settings, SSL and Certificates, Zone WAF
   (Edit) для зоны uaart.com.ua → токен положить в GitHub: репозиторий → Settings → Secrets → Actions →
   CLOUDFLARE_API_TOKEN.
3. После проверки записей автопилотом — у rehost.com.ua заменить ns19/ns20.rehost.com.ua на 2 адреса Cloudflare.
Автопилот (по «да» владельца и «можно» координатора): сверка записей, сертификат, настройки, правило частоты,
проверка сайта/рекламы/поиска до и после; откат — вернуть DNS-серверы rehost (старые записи там остаются).
