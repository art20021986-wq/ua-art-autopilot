4. **`pythonanywhere_approval_gate.py`** — доверенный шлюз на чистом stdlib Python 3.10: default-deny, без `eval`/`exec`/динамического импорта, без произвольной shell-команды из ввода, проверка каждого SHA-256 файла и всего манифеста, allowlist источника (`/home/Carix/autopilot_inbox/cloud/`) и целей, отказ от симлинков и path traversal, прокси-проверка CPU-квоты с порогом 85%, предварительный бэкап перед любой мутацией, атомарная запись квитанции (`os.replace`), жёсткая остановка CRITICAL-действий без отдельной записи Gate B, откат при сбое.

6. **`github_workflow_install_plan.md`** — архитектура из 4 раздельных потоков (транспорт в карантин, генератор манифеста, исполнение Gate A, исполнение Gate B), список необходимых секретов/переменных без значений, точный безопасный порядок операций и поведение при сбое.

## Соответствие требованиям TASK_010

- Gate A и Gate B строго разделены на уровне кода (`verify_gate(manifest, "A")` vs `"B"`, разные `command_id` наборы, `run_gate_a` явно отказывает CRITICAL-командам, `run_gate_b` явно требует отдельную запись `gate_b` и не содержит реализации записи в прод).
- Изменение любого байта файла после одобрения автоматически аннулирует одобрение, так как `manifest_sha256` криптографически зависит от содержимого всех файлов (см. `release_manifest_spec.md`, раздел «Канонизация и хэширование»).
- Claude Chat (через будущий MCP) не может передать в исполнительный слой ни команду, ни путь, ни файл, ни URL — только `task_id`, `manifest_sha256` и текст подтверждения/причины.
- Отсутствие доказательства (SHA, provenance, gate-записи, quota) везде трактуется как отказ, а не как успех.
