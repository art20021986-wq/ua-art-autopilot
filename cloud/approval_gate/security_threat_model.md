# Модель угроз шлюза одобрения релизов — TASK_010

| Угроза | Описание | Контроль |
|---|---|---|
| Случайное одобрение | Владелец случайно присылает фразу одобрения без намерения | Фраза обязана включать точный TASK_ID и полный 64-hex `manifest_sha256`; общее слово `APPROVE` никогда не принимается |
| Устаревшее одобрение | Одобрение выдано давно, ситуация изменилась | Каждая запись `gate_a`/`gate_b` содержит `expires_at_utc`; шлюз отклоняет просроченные записи (`verify_gate`) |
| Изменённые байты после одобрения | Файл поменяли после того как владелец одобрил хэш | `manifest_sha256` криптографически привязан к содержимому всех файлов; при пересборке манифеста хэш меняется, старая запись одобрения физически не совпадает с новым `manifest_sha256` → автоматический default-deny |
| Replay-атака одобрения | Повторное использование той же фразы одобрения для другого релиза | Одобрение проверяется на точное совпадение `task_id` + `manifest_sha256` с ТЕКУЩИМ ожидающим релизом (`approve_release`); одноразовый `nonce` в записи |
| Path traversal | Манифест указывает `../../etc/passwd` как путь | Явная проверка `".." in path.parts`, плюс проверка что resolved-путь начинается с allowlist-корня |
| Симлинк-подмена | Файл/цель — симлинк, указывающий вне allowlist | Явная проверка `Path.is_symlink()` для источников и целей, отказ при истинности |
| Вредоносный/инъецированный манифест | Манифест создан не Claude/Actions, а вручную с ложными хэшами | Обязательные поля `source_commit_sha`, `github_actions_run_id/url`, `claude_authored=true`; шлюз пересчитывает и сверяет каждый SHA-256 с реальными байтами файла в `ALLOWED_SOURCE_ROOT` |
| Prompt injection через Claude Chat/MCP | Инструкция внутри чата пытается заставить MCP выполнить произвольную команду | MCP-инструменты принимают только `task_id`, `manifest_sha256`, `owner_confirmation`/`reason` — никаких полей команд/путей/URL/кода; сервер сам решает, что разрешено, по уже существующему манифесту |
| Инъекция произвольной команды | Попытка передать shell-команду через любое поле | Шлюз использует только `command_id` из хардкод `ALLOWED_COMMAND_IDS`; нет построения строки команды из пользовательского ввода; `eval`/`exec`/`subprocess` с непроверенным вводом отсутствуют |
| Отсутствие бэкапа | Мутация цели без возможности отката | `backup_required` обязателен для любых мутируемых целей; `create_backup_manifest` создаёт копию до действия; Gate B жёстко отказывает при `backup_required=false` |
| Неудачный откат | Backup создан, но откат не сработал | Откат — явная функция `_rollback_from_backup` (в реальной реализации), вызывается в `except`-ветке; при отсутствии успешного отката квитанция обязана фиксировать `outcome=FAILED_ROLLBACK_ATTEMPTED`, а не молчаливый успех |
| Исчерпание CPU | Тяжёлая задача запускается при высокой загрузке PythonAnywhere | `check_cpu_quota_and_maybe_defer` проверяет прокси-нагрузку и отклоняет/откладывает при ≥85%; неизвестная квота никогда не трактуется как разрешение для CRITICAL |
| Параллельный дублирующий деплой | Два процесса одновременно пытаются выполнить один и тот же релиз | Уникальный `run_id` на основе `manifest_sha256` + uuid для квитанций; атомарная запись (`os.replace`) исключает частичную/дублирующую запись; серверное хранилище должно использовать блокировку файла манифеста (описано как обязанность `ReleaseStore`) |
| Скомпрометированный токен | Утечка `PYTHONANYWHERE_API_TOKEN` или owner-секрета MCP | Секреты хранятся только в GitHub Actions Secrets / серверном secret-manager, никогда в коде; `_constant_time_eq` предотвращает тайминг-атаки; рекомендация — ротация токена при подозрении |
| Подделка происхождения (provenance spoofing) | Кто-то утверждает, что файл создан Claude Actions, хотя это не так | Обязательные `github_actions_run_id`/`url` + `source_commit_sha` в манифесте, сверяемые (в полной реализации) с реальным GitHub API; отсутствие проверяемых полей → default deny, а не PASS |
| Отсутствие доказательства = ложное PASS | Любой недостающий признак ошибочно считается успешным | Явный принцип по всему коду: `if record is None: raise GateDenied(...)` — отсутствие данных всегда означает отказ, никогда не толкуется как «всё в порядке» |
