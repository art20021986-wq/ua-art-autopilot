# Рабочий процесс владельца — Шлюз одобрения релизов (TASK_010)

## Кратко (один экран)

1. **ChatGPT/Codex** формулирует задачу → пишет `tasks/task_NNN.md`.
2. **Claude** (через API-воркер) готовит файлы-кандидаты в `cloud/`.
3. Система автоматически считает хэши и формирует **манифест релиза** (SHA-256 каждого файла + общий SHA-256 манифеста). Кандидат копируется ТОЛЬКО в карантин/входящую папку на PythonAnywhere (`autopilot_inbox`). Это НЕ выполнение и НЕ публикация.
4. Владелец получает статус: что именно будет запущено, где, какие хэши, какой риск, это песочница или прод-способное действие.
5. Владелец одобряет ИМЕННО этот манифест конкретной фразой (см. ниже). Одобрение привязано к TASK_ID + SHA-256 манифеста. Если хоть один байт изменится — одобрение автоматически становится недействительным.
6. Только после одобрения доверенный шлюз на стороне PythonAnywhere проверяет происхождение/хэши/allowlist/бэкапы и выполняет ТОЛЬКО одобренное действие.
7. Система создаёт машинную квитанцию (receipt) — доказательство того, что именно произошло.
8. Любая публикация в продакшн требует ВТОРОГО отдельного критического одобрения.

## Статусы кандидата

- `DRAFTED` — Claude подготовил файлы в `cloud/`, манифест ещё не создан.
- `MANIFESTED` — манифест создан, хэши зафиксированы, ждёт передачи в карантин.
- `QUARANTINED` — файлы скопированы в `autopilot_inbox` PythonAnywhere, НЕ выполнялись.
- `AWAITING_GATE_A` — ждёт одобрения безопасного/песочничного запуска.
- `GATE_A_APPROVED` — владелец одобрил безопасный запуск данного манифеста.
- `GATE_A_EXECUTED` — безопасное действие выполнено, квитанция создана.
- `AWAITING_GATE_B` — ждёт критического одобрения публикации в прод.
- `GATE_B_APPROVED` — владелец одобрил именно этот прод-релиз.
- `PRODUCTION_APPLIED` — изменение применено в проде, квитанция создана.
- `REJECTED` — владелец отклонил кандидата.
- `EXPIRED` / `INVALIDATED` — одобрение просрочено или байты изменились после одобрения.

## Точные фразы одобрения

### Карантинная передача
Не требует одобрения фразой — выполняется автоматически, но НИКОГДА не равна выполнению.

### GATE A — безопасный запуск / песочница
```
APPROVE_RUN TASK_010 MANIFEST_SHA256=<64hex>
```
Означает: разрешаю выполнить ТОЛЬКО заявленное в манифесте безопасное/песочничное действие для этого точного набора байт.

Отклонение:
```
REJECT_RUN TASK_010 MANIFEST_SHA256=<64hex> REASON=<причина>
```

### GATE B — критическая публикация в продакшн
```
APPROVE_PRODUCTION TASK_010 MANIFEST_SHA256=<64hex>
```
Означает: разрешаю применить именно этот проверенный релиз в проде (публикация, запись в CRM, reload, удаление, массовая регенерация и т.п.).

GATE A никогда не заменяет GATE B. Одобрение одноразовое и не распространяется на изменённые в будущем байты того же TASK_ID.

## Важно

- Карантин ≠ выполнение.
- Безопасный запуск (Gate A) ≠ публикация в прод.
- Изменение хотя бы одного байта после одобрения аннулирует одобрение автоматически.
- Обычный чат Claude пока НЕ является каналом одобрения — это будущее (см. `claude_owner_approval_mcp.py`), в этой задаче НЕ развёрнуто.
