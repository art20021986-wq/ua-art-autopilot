FIFO — process-safe очередь на основе отдельного SQLite-файла (WAL, `BEGIN IMMEDIATE`) или файлового lock (`fcntl.flock`) поверх JSONL с fsync на каждой записи; операции: `enqueue` (атомарная запись + fsync), `claim` (эксклюзивная блокировка перед drain), `ack` (пометка выполненной), `requeue` при сбое drain.
4. `operation_id` — детерминированный UUID, генерируемый на стороне `cars_ui.py` до попытки записи (не после), сохраняется вместе с операцией; при drain перед применением проверяется, не был ли этот `operation_id` уже применён (таблица/файл `applied_ops` с UNIQUE constraint) — обеспечивает идемпотентность при повторном воспроизведении после крэша.

Поле для записи принимается только через жёсткий allowlist-маппинг `{"price": "price", "mileage": "mileage", ...}` (реальные имена будут подставлены после получения схемы) — сравнение по точному ключу словаря, само значение никогда не интерполируется в SQL-текст; используются только параметризованные запросы с предварительно валидированным именем колонки.
6. `log_action` вызывается асинхронно/в отдельной транзакции после успешного основного commit и не должен откатывать или блокировать основную запись (try/except вокруг log-вызова, ошибки логируются, но не пробрасываются пользователю).
