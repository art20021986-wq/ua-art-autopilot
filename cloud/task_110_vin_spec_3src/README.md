# TASK110 — VIN → дополнительная спецификация

Контракт: `UA-VIN-SPEC-3SRC-V1.0`.

Существующий CRM-процесс по валидному VIN продолжает создавать/открывать
карточку. Новый сервис каждые 30 секунд читает `cars` в режиме SQLite
`query_only`, обнаруживает новый 17-значный VIN и создаёт одну идемпотентную
задачу на текущую версию политики.

Дополнительные характеристики, очередь, происхождение и ручные правки хранятся
в `/home/Carix/vin_specs.db`. Основная `/home/Carix/crm.db` не изменяется.

Для старых карточек production-установка выполняет одноразовый backfill. Для
будущих карточек работает daemon-поток внутри существующего CRM-бота.
Опубликованная ранее карточка обновляется после появления подтверждённых
фактов. Неопубликованная карточка никогда не публикуется автоматически: при
обычной операторской публикации генератор возьмёт уже готовый блок из sidecar.

Файлы:

- `source_policy.py` — allowlist, получение и проверка фактов;
- `vin_spec_service.py` — очередь, sidecar, миграция старых строк и worker;
- `integration_patcher.py` — идемпотентная интеграция с UA099;
- `remote_installer.py` — backup/install/backfill/verify/rollback;
- `controller.py` — CRITICAL production controller;
- `test_contract.py` — офлайн-контракт старых/новых карточек и запрета цен.
