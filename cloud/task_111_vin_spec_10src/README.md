# TASK111 — VIN → дополнительная спецификация из 10 источников

Контракт: `UA-VIN-SPEC-10SRC-V2.0`.

Существующий CRM-процесс по валидному VIN продолжает создавать/открывать
карточку. Сервис каждые 30 секунд читает `cars` в режиме SQLite `query_only`,
обнаруживает новый 17-значный VIN и создаёт одну идемпотентную задачу на
текущую версию политики. Смена версии политики автоматически ставит в очередь
и все старые VIN.

Рабочий пул состоит ровно из десяти нероссийских источников: NHTSA vPIC,
Auto-Data, CarWiki, Danawa Auto, CarIsYou, UltimateSpecs,
Automobile-Catalog, Cars-Data, Carfolio и EncyCARpedia. Для известных
VIN-семейств используются точные проверенные страницы модификации и
версионированный каталог подтверждённых значений; для будущих неизвестных VIN
работает поиск точной модификации по всем десяти доменам. Поисковик служит
только для обнаружения URL и не является источником факта.

Дополнительные характеристики, очередь, происхождение и ручные правки хранятся
в `/home/Carix/vin_specs.db`. Основная `/home/Carix/crm.db` не изменяется.
Год, декодированный из VIN, используется только для поиска и никогда не
перезаписывает операторский год CRM.

Production-установка выполняет полный backfill. Выпуск считается успешным,
только если все 16 опубликованных карточек имеют не менее 10 видимых
характеристик. Для будущих карточек daemon-поток запускается внутри
существующего CRM-бота. Ранее опубликованная карточка обновляется после сбора;
неопубликованная карточка не публикуется автоматически.

Файлы:

- `profile_library.py` — точные VIN-профили и проверенный каталог значений;
- `source_policy.py` — allowlist, поиск, получение, проверка и разрешение конфликтов;
- `vin_spec_service.py` — очередь, sidecar, миграция и автоматический worker;
- `integration_patcher.py` — идемпотентная интеграция с CRM;
- `remote_installer.py` — backup/install/backfill/verify/rollback;
- `controller.py` — CRITICAL production controller;
- `test_contract.py` — офлайн-контракт всех старых/новых карточек и запрета цен.
