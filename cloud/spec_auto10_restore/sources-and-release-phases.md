# Источники и допустимый выпуск: ограниченная проверка

Дата: 09.09.2026. Источники проверены по локальному коду и сохранённым доказательствам; управление выпуском дополнительно прочитано через GitHub connector в 05:58 UTC. Запросов к десяти источникам, запусков рабочих процессов, изменений CRM, сайта или управляющих флагов в этом шаге не было. **Общий Gate B этим отчётом не закрывается.**

## Что доказано по десяти источникам

В `runtime/source_policy.py` сохранены исходные десять доменов. `source_probe.py` без `--network` не делает запросов. С `--network` текущая реализация имеет следующий предел:

| Проверка | Что реально проверяет | Допустимый итог сейчас |
|---|---|---|
| vpic.nhtsa.dot.gov | Общий JSON со списком моделей Kia; VIN не отправляется | `API_SCHEMA_ONLY`, не проверка декодера VIN и не технический `PASS` |
| carisyou.com | Контрольный старый URL не имеет проверенной идентичности автомобиля | `NOT_RUN`; HTTP-запрос намеренно не выполняется |
| auto-data.net, carwiki.co.kr, auto.danawa.com, ultimatespecs.com, automobile-catalog.com, cars-data.com, carfolio.com, encycarpedia.com | Страница контрольной модели, сопоставление и извлечение минимум четырёх допустимых полей | До **восьми** технических `PASS`, если реальные ответы соответствуют проверкам |

Следовательно, текущий CLI **не может получить 10/10 PASS**. Его код выхода `2` при `--network` сам по себе не означает неисправность всех источников: условие успешного выхода требует десять `PASS`, хотя два вышеописанных результата заведомо имеют другие статусы. Общая доступность страницы также не подтверждает заводскую комплектацию отдельного VIN.

Сохранённая локальная попытка ([sources-local-live-20260909.json](evidence/sources-local-live-20260909.json)) содержит **одну** попытку обращения к vPIC, завершившуюся `URLError` через **5,007 секунды**. Проверенных HTTP-ответов — **ноль**. Последующие обращения прекращены; остальные девять доменов не проверялись. Инструмент отдельно сообщил `network approval was cancelled before a decision was returned` — запрос разрешения отменён до решения. В процессе `policy_denial_explicit` был `false`.

Из этих данных нельзя вывести отказ десяти сайтов, HTTP 403/429, запрет VIN-декодера или поломку восьми адаптеров. Переключение маршрута для обхода ограничения не выполнялось. До установления разрешённого способа сетевой проверки статусы остаются `NOT_RUN`.

## Следующая проверка после определения разрешённого способа

Это план технической доработки и проверки; команды здесь не исполнялись.

1. Зафиксировать хеши проверяемых адаптеров и среду исполнения. Изолированный серверный тест без сети и проверка десяти источников должны иметь отдельные отчёты.
2. Для каждого домена задать контрольную страницу и ожидаемые марку, модель, допустимый год, топливо и объём двигателя. Для Carisyou сначала технически проверить подходящую контрольную страницу; старый URL без такой проверки не повышать до `PASS`.
3. Выполнить только разрешённые ограниченные GET с существующей проверкой доменов и перенаправлений. По каждому результату отдельно записать доступ, соответствие автомобиля, извлечённые поля и происхождение данных. На явном запрете сети прекратить обращения; не использовать другой маршрут. HTTP 429 учитывать с `Retry-After`, без обхода или немедленного повторения.
4. Для vPIC отдельно проверить декодирование на согласованной идентичности из текущей CRM и строго сравнить ответ. Общий список моделей оставить самостоятельной проверкой схемы. В публичном отчёте не выводить полный VIN. Короткие японские номера кузова не отправлять как стандартный VIN.
5. Разделить итог CLI: «проверки выполнены» и «адаптер пригоден». Не считать `API_SCHEMA_ONLY`, `NOT_RUN`, несоответствие модели или сохранённый профиль техническим успехом. Общая готовность требует фактического результата каждого из десяти адаптеров на применимом примере; она не требует десяти успешных источников для каждого автомобиля.

Текущий probe не сохраняет достаточно сведений для различения DNS/TLS/таймаута и запрета среды: транспорт сводится к `NETWORK_<тип исключения>`. При доработке нужны безопасные категории причины, времена и подтверждённый HTTP-статус, без вывода секретов или предположения о причине отказа сайта.

## Конкретное изменение управления, требующее отдельного решения

Предлагаемый предмет задания — **[UA-ART-RECOVERY-TASK120-002 v1.0](RECOVERY-TASK120-002.md)**, подготовка штатной процедуры завершения именно остановки TASK120. Это отдельное ТЗ с точными привязками, этапами PR/dry-run и критериями приёмки, а не уже существующая возможность и не разрешение сейчас снять флаг.

1. Read-only preflight связывает исходный HALT по SHA, epoch, run и request с reconciliation; проверяет отсутствие всех незавершённых транзакций, активных writers и непросмотренных запусков в очереди. Неоднозначность останавливает процедуру.
2. Dry-run формирует точный перечень будущих изменений управления и неизменяемый архив исходной остановки. Исходный неуспешный TASK120 и его consumed launch остаются историей; автоматического повторения нет.
3. Отдельное утверждение владельца связывается с этим планом и его SHA. Любой дрейф main/HALT/плана до исполнения требует нового preflight. Закреплённый runtime manifest обновляется только вместе с проверенным изменением кода; действующие проверки owner/Gate B/backup/live receipt/health/exact launch не ослабляются.
4. Переход реализуется штатным проверенным контроллером с атомарной фиксацией, аудитом и защитой от повторного исполнения. До завершения всех условий HALT остаётся в силе. Изолированные тесты обязаны проверять неверный SHA/epoch, pending transaction, повтор, дрейф и сбой фиксации.
5. Снятие остановки само не публикует автомобили и не запускает TASK120. Выпуск спецификации и последующий выпуск UA-0017/UA-0018 проходят свои уже согласованные предметные проверки и штатный запуск. Если процедура не может исключить нежелательный старт старой очереди, она не готова к утверждению на исполнение.

Единственное новое решение, которое выявил этот обзор: включить в работу подготовку и проверку такой процедуры управления. Перед фактическим исполнением владельцу нужен её конкретный dry-run и результат тестов; этот отчёт их не подменяет. Здесь изменение не реализовано и не исполнялось.

## Что остаётся после исправления errno 22

Исправление сборщика закрывает только совместимость сборки. Для общего заключения нужно свести отдельные доказательства серверного прогона, активных модулей и БД, полного publisher и возврата, проверок десяти адаптеров, задержек восстановления и допустимого перехода из остановленного состояния. Статус параллельных серверных проверок этот ограниченный отчёт не переоценивает. Подготовленный Preview и сохранённые характеристики не подменяют проверку десяти адаптеров и управление выпуском.

Нового решения владельца по списку источников или выбору технической контрольной страницы сейчас не требуется. Уже полученные предметные согласования не нужно запрашивать повторно. Вопросы владельцу следует задавать **по одному**: сначала конкретное изменение управления выше, затем только фактические неоднозначности, если их обнаружит аудит карточек.

UA-0017/UA-0018 этим шагом не публиковались; текущий отчёт не разрешает их автоматический выпуск и не запускает TASK120.
