# Единый кандидат из 15 модулей

**Собран и проверен локально. 12/12 проверок сборки PASS. Общий Gate B этим не закрывается.**

`complete_candidate.py` объединяет точные десять модулей v7, проверенный worker v8, исправления `master_card` и контракта единственного VIN, а также исправления трёх входов создания карточек и новый генератор номеров. Исходники приложения не импортируются: выполняются только закреплённые чистые преобразователи текста, затем компиляция каждого результата в памяти.

Последний кандидат: `/workspace/scratch/2d59224df460/private-runtime/complete-candidate15-v1-r2`. [Манифест](evidence/complete15-candidate-manifest.json), [результат](evidence/complete15-candidate-result.json), [журнал 12 проверок](evidence/complete15-candidate-tests.log).

| Включено в точный набор из 15 | Назначение |
|---|---|
| `vin_spec_service`, `source_policy`, `profile_library` | Очередь, восстановление, политика источников |
| `spec_publication`, `card_shell`, `card_lifecycle` | Спецификация, один VIN, согласованные операции карточек |
| `cars_ui`, `publikaciya`, `publish_transaction_guard`, `ua_additional_spec` | Интеграция действующего CRM и publisher |
| `master_card` | Удаление точно установленного устаревшего CSS, менявшего оболочку |
| `cars_schema`, `db`, `ai_filter`, `car_number_allocator` | Создание карточек без повторного использования удалённых номеров |

`stranica.py`, `catalog_design_guard.py` и эталон каталога записаны отдельными неизменными зависимостями исполнения. Они не добавлены в установочный набор из 15.

## Проверки сборщика

Заранее закреплены SHA исходных v7, двух новых runtime-файлов, семи исходных захватов/зависимостей, четырёх инструментов преобразования и всех 15 результатов. Отсутствующий, лишний, уже изменённый или перенесённый для теста исходник отклоняется. Старый `prepare_candidate.py` по-прежнему принимает ровно десять модулей; его код и глобальные списки не менялись.

Новый каталог создаётся исключительно. Готовые файлы добавляются без перезаписи, манифест — последним; `renameat2` не используется. Проверяются хеши и состав до и после записи, неизменность исходников, запрет символьных ссылок и повторной записи. Если исходник изменился после фиксации, удаляется только собственный завершающий манифест, и каталог больше не проходит проверку готовности. Тесты также подтверждают запрет подмены статуса Gate B, признаков production и ограничений в манифесте.

Локальный каталог v7 содержал производный Python-кеш. Его исходные десять файлов и манифест без изменений перенесены в отдельный каталог `complete15-base-v7-clean`; существующий v7 не очищался и не переписывался. Строгая проверка использует новый точный набор, а не игнорирует произвольные лишние файлы.

## Использование манифеста при дальнейшем выпуске

Поле `files.changed` сравнивает **только входы этой сборки**, а не рабочий сервер. Например, новый для production `car_number_allocator.py` скопирован из подготовленного runtime без изменения и поэтому имеет `changed: false`. Это не означает, что его можно пропустить.

Будущий installer должен использовать **все 15 явных целей**, отдельно проверить фактические рабочие байты существующих файлов и условие отсутствия новых файлов. Фильтровать установку по `files.changed` нельзя. `input_bindings` — информационные локальные пути сборки; они не доказывают привязку текущего процесса и не являются планом установки.

Серверные проверки worker, publisher и allocator относятся к своим отдельно записанным наборам. Они не объявляют прошедшим исполнение объединённого набора из 15. Полный совместный прогон, рабочие привязки, резерв, контролируемый выпуск и live-проверка остаются последующими условиями. Этот этап не изменил CRM, сайт, карточки, процессы или HALT.

Для повторной проверки готового каталога:

```bash
python -B cloud/spec_auto10_restore/complete_candidate.py --verify --output /absolute/path/to/complete-candidate
```

Для сборки используются `--base-candidate`, `--sources-json` и `--output`. JSON должен содержать ровно семь ключей из `SOURCE_PINS` с путями к соответствующим исходным захватам. Результат можно записать только в новый каталог, расположенный отдельно от всех входов.
