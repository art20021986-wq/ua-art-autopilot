## Что запускается дальше

`source_acceptance.py` выполняет только явные GET из `source_acceptance_plan.json`, без discovery/search, CRM, публикации и сохранения фактов. Загрузка ограничена двумя закреплёнными чистыми модулями: `source_policy.py` и `profile_library.py`. Выполняются именно проверенные по SHA байты, повторного чтения перед исполнением нет. VIN отсутствует в исходном плане и не отправляется.

Пределы: 90 секунд на процесс, 8 секунд ожидания запроса, до 2 МБ ответа, до двух перенаправлений только внутри исходного источника, ноль повторов. Десять первоначальных GET плюс максимум двадцать разрешённых перенаправлений. Первый транспортный отказ прекращает все оставшиеся обращения; исключения классифицируются без публикации их потенциально чувствительного текста. HTTP 429 сохраняется отдельно с Retry-After, без повтора. Это не разрешение обходить ограничения среды.

Доступность, результат контрольного сопоставления и пригодность адаптера записываются отдельно. `probe_execution_complete` означает завершение запланированных попыток, `all_ten_adapters_pass` — десять действительных результатов адаптеров; одно не заменяет другое. Код возврата: `0` для корректного offline-плана или live 10/10 адаптеров, `2` при неполной live-приёмке, `3` при отказе по входным данным/runtime.

## Точный следующий шаг

Сначала определить разрешённую среду сетевого исполнения. Предыдущая локальная попытка закончилась `network approval was cancelled before a decision was returned`; здесь она не повторялась и через PythonAnywhere/браузер/другой маршрут не обходилась. Наличие `--network` или `--authorization-ref` не отменяет требований среды.

После определения такого маршрута запустить пакет рядом с **новым общим кандидатом**, содержащим два закреплённых runtime-файла. Offline-команда, уже проверенная на локальной точной копии:

```bash
python3.10 -B source_acceptance.py \
  --plan source_acceptance_plan.json \
  --runtime /absolute/path/to/new-joint-candidate \
  --plan-sha256 c950c34d7fbbefdf499357d1df0e8f55ea20cc4b9db7cd1121af703d47dd07ad
```

Только при действующем разрешённом доступе добавляются `--network --execution-origin '<реальный worker/run>' --authorization-ref '<ссылка на действующее основание запуска>'`. Зафиксировать stdout и код возврата без объявления публикации или Gate B PASS.

По полученным данным: проверить видимый автомобиль старого Carisyou URL, выбрать подходящую контрольную страницу при необходимости, внести подтверждённый контекст и SHA материала его технической проверки в новую версию плана. Пользователю не требуется выбирать техническую страницу. Непроверенный URL не повышать до PASS.

Для vPIC новая версия плана поддерживает `vin_decode` с `control={vin_sha256, car}` и отдельным `control_review`. Полный VIN берётся только из приватного JSON `{"vin":"..."}` через `--private-vin-input`; хеш и контекст должны относиться к уже разрешённому точному контрольному автомобилю. Японский номер кузова не принимается как VIN. В отчёте URL и идентичность VIN скрываются; факт попытки запроса отделён от подтверждённого получения HTTP-ответа. Совпадение VIN, марки, модели, года и ErrorCode=0 обязательно. Наличие данных в плане само по себе не является разрешением передачи VIN.

После действительных результатов каждого применимого контрольного адаптера предметная приёмка источников объединяется с Gate B. Требование десяти адаптеров сохраняется; десять успешных ответов для каждого отдельного автомобиля не требуются. Недоступность одного источника не разрешает замену характеристик чужой комплектацией. Этот read-only инструмент не может стереть последние достоверные факты; сохранность существующих фактов при сбое проверяется отдельно в общем CRM/worker-сценарии.
