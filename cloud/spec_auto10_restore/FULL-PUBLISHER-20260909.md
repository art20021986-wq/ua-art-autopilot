# Полный publisher: изолированная проверка 09.09.2026

**Локально и на серверном Python 3.10 PASS. Рабочая CRM и сайт не изменены. Общий Gate B этим не закрыт.**

Серверный прогон завершён **09.09.2026 в 08:18:03 UTC**: восемь проверок guard PASS, четыре основные страницы и два каталога PASS, повтор штатным publisher PASS, восемь плохих вариантов страниц отвергнуты. При ошибке второго каталога **пять действительно изменённых HTML** возвращены побайтно. Все 14 наблюдаемых входных файлов сохранили SHA и mtime; счётчики внешних чтений, записей, сети и процессов — 0. [Серверная сводка](evidence/publisher-server-v2-summary.json), [полный серверный результат](evidence/publisher-server-v2-result.json).

Первая серверная попытка остановилась до тестовых страниц: Python 3.10 передал SQLite-путь как `bytes`, тогда как guard ожидал строку. В версии стенда 2 добавлено декодирование файлового пути; проверка границ осталась прежней и дополнена регрессией для байтовых путей и кодированного внешнего URI. Production patcher этой поправкой не менялись. [Сохранённый первый отказ](evidence/publisher-server-v1-result.json), [состав версии 2](evidence/full-publisher-server-bundle-v2.json).

Впервые выполнен полный путь текущего publisher: `publish_batch` → действующие
`stranica` и `master_card` → основные страницы и диагностика → оба каталога через
реальный `catalog_design_golden.html` → фактическая проверка комплекта и откат.
Затем отдельно выполнен штатный `publikaciya.opublikovat` для повторной публикации.
13 модулей взяты из сверенных копий, включая кандидат worker v8. Запущенный бот
не импортировался и не перезапускался. CRM, факты и фотографии в стенде синтетические.

## Два найденных несовпадения и исправления

1. Текущий `master_card.CHAT_CSS` добавлял к новой странице старый мобильный
   стиль чата, отсутствующий на всех 32 ранее проверенных страницах. Это меняло
   оболочку и законно блокировалось проверкой `UNREVIEWED_NEW_CARD_SHELL_ASSETS`.
   `repair_master_shell.py` требует точный SHA всего исходника и SHA одного
   строкового литерала; заменяет только этот литерал на пустую строку. AST
   проверяет границу изменения. Прежний утверждённый SHA оболочки сохранён.

2. Старый `public_contract_errors` требовал дополнительную панель VIN, которую
   восстановление правильно удаляет. `repair_public_contract.py` сохраняет
   остальные старые проверки и заменяет три условия старой VIN-панели на
   каноническую спецификацию, единственный видимый VIN, его совпадение с CRM,
   неизменную оболочку и порядок «спецификация перед этапами».

Оба patcher работают со строками и не выполняют исходники. Неизвестный исходный
SHA отвергается. Новая публикация не получает разрешения изменять старый SHA
оболочки; проверка не ослаблена принятием нового оформления.

## Фактически пройдено

- Публикация двух синтетических автомобилей: четыре основные страницы, четыре
  диагностики и два каталога. На каждой основной странице один VIN и один
  синтетический подтверждённый факт; оба каталога сохраняют оболочку golden.
- Повтор через штатный `opublikovat`: сохраняются данные и оболочка. Меняются
  только известные параметры версии URL и надпись времени генерации; побайтовая
  идентичность полной пересборки не заявляется.
- Непустой откат: до публикации изменена синтетическая цена 15000 → 16000,
  искусственная однократная ошибка вызвана при записи второго каталога.
  В локальном прогоне к этому моменту три HTML действительно изменились, на сервере — пять. Реальный
  `Snapshot.restore` восстановил их, весь набор HTML совпал с прежним побайтно. Цена в тестовой
  БД после сценария отдельно возвращена к 15000.
- Отвергнуты восемь плохих страниц: без спецификации, с повторным VIN, с чужим
  единственным VIN, подменённым фактом, без диагностики, неверным действием,
  добавленным CSS и спецификацией после этапов.
- Семь целевых проверок Python guard: запрет внешних файлов, SQLite, сети,
  запуска процессов, выхода через symlink/dirfd; точная замена литералов;
  отказ неизвестных patcher-исходников и существующего выходного каталога.

## Граница проверки

Это проверка доверенного снятого кода в отдельном процессе с Python audit guard,
а не защитная песочница для враждебных native extensions. В реальном прогоне
счётчики запрещённых чтений, записей, сети и процессов равны нулю. Перед импортом
буквальные пути `/home/Carix` переносятся в новый стенд; AST подтверждает, что
кроме двух явных исправлений менялись только эти пути. Окружение очищается,
поисковые пути импорта ограничены стендом и системными библиотеками.

Публикация реальных UA-0017/UA-0018, полный пользовательский цикл удаления и
добавления через новый allocator, привязка активного worker, десять сетевых
источников и рабочий postcheck не подтверждаются данным прогоном. Вопрос
непоследовательного времени в старом шаблоне также не считается исправленным.

Фактически исполнен пакет `publisher-server-gate-v2.zip`, SHA256
`6ad70d08b429224d38a74acf8407eec2847bcbba597edcf1133e28764267d228`.
Он содержит runner, два patcher, восемь тестов и хеши; production-исходники в ZIP
не включены. Launcher проверил 14 входных файлов до и после, выполнил child
только в `/home/Carix/spec_publisher_gate_20260909/run-20260909T081750274827Z`.
Серверные JSON получены штатным скачиванием и сверены с SHA сервера.
