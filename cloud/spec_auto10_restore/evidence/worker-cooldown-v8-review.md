# Независимая проверка восстановления очереди v8

**Результат: PASS в пределах изменения повторов синхронизации сайта.** Блокирующих замечаний к проверенному изменению не обнаружено. Это заключение не переносит серверные результаты v7 на v8 и не закрывает общий Gate B.

Сравнение выполнено с неизменённым `private-runtime/candidate-errno22-v7/vin_spec_service.py`. Проверены пять участков изменения: интервал сверки, добавление срока для старых FAILED, восстановление просроченного последнего захвата, повторная постановка FAILED и назначение паузы после третьей ошибки.

Независимо выполнено **31/31 проверок PASS**, без ошибок и пропусков: `python3 -m unittest discover -s cloud/spec_auto10_restore/tests -p test_worker_recovery.py -v`. Продолжительность — 0,528 секунды. Использованы временные SQLite/HTML, подставленные ответы источников и локальный reconciler; действий с рабочей CRM, сайтом и сетью не выполнялось. SHA сервиса после прогона совпадает с зафиксированным. Протокол автора на 50 проверок worker/lifecycle рассматривается отдельно и не складывается с повторно выполненными 31 проверками.

Подтверждено:

- В v7 `site_sync_status=FAILED` исключался из обычной повторной постановки. В v8 эта же опубликованная карточка автоматически возвращается в PENDING после записанного срока. Изменение VIN/контекста, снятие с публикации и удаление не превращаются в разрешение восстановить старую страницу.
- После третьей ошибки сохраняются FAILED, последняя причина и исчерпанный счётчик до конца паузы. Обычный просмотр очереди и повторная инициализация не сокращают и не продлевают уже записанную паузу. Старой записи без срока назначается один срок.
- Пауза по умолчанию составляет 300 секунд, допустимая настройка — 60–300 секунд. Постоянная ошибка приводит к последующим сериям максимум по три попытки с паузами между сериями. Это намеренные периодические повторы, а не конечное общее число попыток; непрерывного быстрого цикла нет.
- Постановка в очередь выполняется под прежней SQLite-транзакцией `BEGIN IMMEDIATE`, требует отсутствия токена и совпадения идентичности. Два конкурирующих прохода дают одну постановку и один захват. Непросроченный захват не перехватывается; финальный просроченный захват получает паузу до следующей серии.
- Восстановление использует сохранённые характеристики. Оно не сбрасывает бюджет сбора источников, не меняет политику источников, ручные значения и признаки видимости. Проверка настоящим локальным `spec_publication` восстановила оба HTML с ручным значением и одним VIN после трёх отказов.
- По прямому сравнению пяти общих модулей с v7 `source_policy.py`, `profile_library.py`, `spec_publication.py`, `card_shell.py` и `card_lifecycle.py` не менялись. Правила tombstone, публикационные блокировки и сохранения характеристик этим изменением не расширяются.

Ограничения приёмки сохраняются. Проверки сроков используют искусственно наступившие значения времени; серверный SLA не измерен. Последовательная обработка очереди, продолжительность сетевого сбора, реальные настройки сервера и прежний срок аренды 1800 секунд могут влиять на время восстановления. Исчерпание собственно сетевого сбора источников этим изменением не устранено. Для выпуска требуется отдельная проверка собранного v8 на разрешённом стенде с его фактическими SHA; серверный результат v7 **182/182** к этому новому коду автоматически не относится.
