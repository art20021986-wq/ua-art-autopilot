## Что исправлено

- Очередь учитывает изменение VIN, марки, модели, года, топлива, двигателя и трансмиссии. Повтор события не создаёт дубли; устаревший результат не заменяет актуальную задачу.
- Сбор фактов и проверка обновления сайта имеют отдельные состояния. Ошибка синхронизации повторяется независимо от обхода источников.
- Для опубликованных карточек подготовлена периодическая сверка, включая READY. Удалённый раздел восстанавливается из сохранённых фактов; ограниченные повторы завершаются явной ошибкой, если восстановление невозможно.
- Пустой ответ не стирает прежние факты, автоматическое обновление не заменяет ручные значения. При изменении идентичности старые параметры сохраняются для проверки и не подставляются другому автомобилю.
- Ошибки внешних запросов имеют срок кеширования. Сопоставление модели стало строже; сохранённые профили применяются только к ранее проверенным точным VIN.
- Публикация проверяет единственный раздел, сохранность прежних ключей и отсутствие рекламы. Универсальный порог «минимум десять строк» убран; пустой раздел не считается заполненным.
- Обычная клавиатура CRM не требует кнопки спецификации. Существующая обёртка регистрации TASK117/TASK121 сохраняется, worker запускается один раз, остальные кнопки не меняются.

Причина отсутствия автоматического восстановления доказана в коде и воспроизведена локальными тестами. **Первый исторический процесс, удаливший раздел, пока не установлен.** Наличие сохранённых фактов и дефект повторной обработки не доказывают, кто первоначально заменил HTML.

## Воспроизведение на изолированной копии

Из корня репозитория:

```bash
python3 -B -m unittest discover -s cloud/spec_auto10_restore/tests -p 'test_*.py'
python3 -B cloud/spec_auto10_restore/source_probe.py
```

Последняя команда без `--network` выдаёт десять NOT_RUN, не обращаясь к внешним сайтам. Текущая проверка десяти адаптеров из среды реального worker ещё не выполнена: получено сообщение «network approval was cancelled before a decision was returned» — запрос разрешения отменён до решения, а не отклонён. Это не результат проверки доступности источников; обход не выполнялся.

Офлайн-сборка из проверенных исходников:

```bash
python3 -B cloud/spec_auto10_restore/prepare_candidate.py --source /tmp/ua-art-reviewed-runtime --output /tmp/ua-art-spec-candidate
```

В `--source` должны лежать `ua_additional_spec.py`, `publikaciya.py`, `publish_transaction_guard.py` и `cars_ui.py`. Новый `--output` располагается вне каталога исходников. Неизвестные сигнатуры и изменённые блоки патчей отклоняются. Кандидат из текущих файлов уже скомпилирован; его нельзя автоматически копировать поверх работающего приложения до допуска Gate B.

Экспорт подтверждённых сохранённых данных на локальной копии:

```bash
python3 -B cloud/spec_auto10_restore/build_verified_specs.py --spec-db /tmp/reviewed-spec.db --crm-db /tmp/reviewed-crm.db --output-dir /tmp/spec-preview-evidence
```

Использовать только копии с проверенными семантическими хешами. Экспорт не изменяет БД и не делает сетевых запросов. На 32 полных сохранённых HTML (16 карточек, пути `video` и `site`) проверены вставка и две повторные пересборки: 96 операций, 0 изменённых байтов вне раздела. [all-card-rebuild.json](evidence/all-card-rebuild.json). Исходные страницы и базы неизменны; актуальность live HTML проверяется отдельно.

## Что нажимать владельцу после внедрения

1. Открыть обычное создание автомобиля в CRM, внести VIN или применимый номер кузова и сохранить данные.
2. Спецификация собирается автоматически. При уточнении идентификатора или значимых данных запускается новая проверка.
3. Для размещения автомобиля использовать привычную кнопку публикации в каталог. HTML-ссылка выдаётся после проверки страницы; спецификация входит в неё автоматически.

Для существующих опубликованных карточек отдельные нажатия спецификации не нужны: сверка и восстановление выполняются автоматически. Черновик от этого не публикуется. Статусы «характеристики собраны» и «страница обновлена» показываются раздельно. Этот сценарий подготовлен в коде, но ещё не проверен после внедрения на рабочем интерфейсе.

## Дополнительные проверки раунда 2

Подтверждён и исправлен обход конфликта UA-0016: прежний exact-VIN профиль и старый READY-job могли допускать автоматическую публикацию при противоречащем годе CRM. Теперь обе очереди дают NEEDS_REVIEW; повтор, canonical load_facts, legacy render/inject и непосредственный reconciler не обходят проверку. Значения, is_manual, is_visible и verification_status остаются неизменны, причина фиксируется в аудите. Проверены также допустимое расхождение года на один год и числовой европейский chassis code.

Инвентаризация задач дополнена ежедневным TASK083. По коду проверенной версии он не переписывает отдельные карточки и не установлен как причина исчезновения раздела; свои генераторы и каталоги он меняет напрямую, а возврат не защищён CAS. Это требует учёта при проверке всех путей записи, но не является основанием автоматически отключать задачу. Установленная версия и исторический журнал не проверены; наблюдённая ссылка журнала блокируется браузером, обхода не было. [scheduled-writer-review.json](evidence/scheduled-writer-review.json).
