## Изменения в кандидате

- Сбор фактов и синхронизация сайта разделены; READY больше не исключает периодическую сверку опубликованного раздела.
- Изменение VIN/модели/года/двигателя инвалидирует устаревшую задачу. Пустой ответ не стирает факты; ручные значения защищены.
- Повторы ограничены и завершаются явной ошибкой. Внешние ошибки имеют срок кеширования; точный VIN не отменяет проверку конфликтов CRM.
- Публикация проверяет канонический раздел, прежние поля и отсутствие рекламы. Универсальный минимум десять строк снят.
- Обычная клавиатура не требует кнопки спецификации; существующая обёртка запуска worker сохраняется.
- `card_shell.py` подключён к композиции спецификации и удаляет известные дубли VIN, оставляя VIN основной таблицы. Интегрированная проверка на 32 cached HTML / 96 операций пройдена; текущий рабочий HTML ещё не аттестован.
- Worker прекращает устаревшие задачи при удалении/смене UID и скрытии карточки, сохраняет факты для аудита и не создаёт удалённые страницы. Транзакционная интеграция текущих обработчиков с общим lock и возвратом объединена: 26 handler-fixture и семь wiring-проверок PASS. Реальные команды действующему боту не отправлялись.

Дефект отсутствия автоматического восстановления воспроизведён. **Первый исторический процесс, удаливший раздел, не установлен.**

## Рабочий сценарий после внедрения

1. Создать автомобиль в обычном CRM-интерфейсе, внести VIN/применимый номер кузова и сохранить данные.
2. Сбор начинается автоматически; уточнение идентичности запускает новую проверку.
3. Использовать обычную публикацию в каталог. Проверенная HTML-ссылка и спецификация должны появиться вместе.

Существующим опубликованным карточкам отдельное нажатие спецификации не требуется. Черновики автоматически не публикуются. Статусы сбора и обновления страницы разделены. Сценарий подготовлен в коде; действующий интерфейс после внедрения ещё не проверен.

## Незавершённый допуск

В main `2ce0c3a886f124c5865c564a7073ef1805861f1c` подтверждён **EMERGENCY_HALT** от TASK120 / run **34134692609**. Проверка автоматического режима возвращает **AUTOMATIC_MODE_HALTED**. Штатный универсальный путь снятия остановки не найден; recovery-исключение не разрешает произвольный запуск. [production-release-control.json](evidence/production-release-control.json).

Это существующий контроль выпуска, не отсутствие команды владельца и не отказ автоматического approval-review. Команда размещения не позволяет обходить его прямой правкой флага или другим маршрутом.

Локальный кандидат из десяти модулей скомпилирован, 169 проверок пройдены, интеграции объединены, Preview версии 3 размещён. Пакет для Python 3.10 загружен штатным интерфейсом на сервер в отдельное изолированное место; серверная попытка завершилась FAIL до тестов; точный результат приведён ниже.

Осталось устранить несовместимость атомарной сборки и завершить серверный прогон, подтвердить активные runtime/БД и актуальные страницы, полный реальный publisher и возврат, подготовить точную правку года UA-0016, проверить десять адаптеров и измерить сроки восстановления. Нужен допустимый системный переход из EMERGENCY_HALT. Локальные PASS и отдельный Preview не закрывают эти условия.

Условия и возврат — [Gate-B.md](Gate-B.md). **Повторное разрешение на размещение не требуется; технические условия Gate B пока не выполнены.**

Пакет v5 загружен штатно и запущен в отдельной папке PythonAnywhere. Python **3.10.12**, семь текущих исходников прошли сверку SHA. Сборка кандидата остановилась **до тестов**: `OSError`, `errno 22`, этап `candidate_compile`. Нужно обеспечить поддерживаемую атомарную сборку без перезаписи чужого результата и повторить серверный прогон. Это совместимость проверочного сборщика; обычная замена HTML и полный рабочий publisher этим результатом не проверены. Новая запись в production, изменение CRM, запуск приложения, сетевые обращения к десяти источникам и перезапуск бота не выполнялись. Только отдельные staging-файлы и временный каталог теста были созданы.
