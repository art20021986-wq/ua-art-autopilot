## Результат

- Очередь сбора учитывает изменение VIN, марки, модели, года, топлива, двигателя и трансмиссии. Повтор события не создаёт дубли; устаревший результат не заменяет актуальную задачу.
- Подготовка фактов и проверка их появления на сайте имеют отдельные состояния. Неуспешная публикация больше не выдаётся за успешное обновление страницы.
- Для опубликованных карточек подготовлена периодическая сверка, в том числе при READY. Восстановление раздела читает сохранённые факты без повторного сбора источников. Ошибки имеют ограниченные повторы; после исчерпания попыток остаётся явное состояние FAILED.
- Фоновый цикл сообщает о состоянии и исключениях. Очереди сбора и синхронизации чередуются: старые страницы не должны постоянно вытеснять новый автомобиль.
- Пустые ответы источников не стирают прежние данные; автоматическое обновление не заменяет ручные значения. При изменении идентичности автомобиля прежние факты сохраняются для проверки и скрываются от новой спецификации.
- У кеша неудачных запросов появился срок действия. Проверка модификации стала строже; профиль из сохранённого справочника разрешён только для ранее проверенного точного VIN.
- Финальная публикация использует каноническое хранилище фактов, проверяет единственный раздел и не допускает потери прежних ключей/строк. Произвольного запрета на публикацию 1–9 подтверждённых фактов нет. Пустой раздел не считается заполненной спецификацией.
- Кнопка `Дополнительная спецификация` исключается из обычной клавиатуры карточки. Остальные кнопки сохраняются; автоматический worker подключается через существующий register-hook.

Эти свойства проверены в изолированных тестах. Их действие в установленной CRM и охват всех реальных путей записи ещё требуют Gate B.

## Офлайн-проверки

Из корня репозитория:

```bash
python3 -B -m unittest discover -s cloud/spec_auto10_restore/tests -p 'test_*.py'
python3 -B cloud/spec_auto10_restore/build_preview.py
python3 -B cloud/spec_auto10_restore/source_probe.py
```

Последняя команда без `--network` выдаёт десять NOT_RUN и не обращается к внешним сайтам. Число доменов в конфигурации не является результатом сетевого теста.

Для офлайн-сборки нужны текущие исходники `ua_additional_spec.py`, `publikaciya.py`, `publish_transaction_guard.py`, `cars_ui.py`, скопированные в отдельный плоский каталог. Затем:

```bash
python3 -B cloud/spec_auto10_restore/prepare_candidate.py --source /tmp/ua-art-reviewed-runtime --output /tmp/ua-art-spec-candidate
```

`--output` должен отсутствовать и находиться вне каталога исходников. Неизвестные сигнатуры или изменённые блоки патчей отклоняются. Структурное совпадение не доказывает, что именно эти файлы загружены рабочими процессами. Копировать результат поверх runtime автоматически нельзя.

## Что нажимать владельцу

После внедрения и проверки на реальном интерфейсе: заполнить/исправить данные автомобиля и выполнить обычное сохранение карточки. Отдельное нажатие кнопки спецификации не потребуется. Для уже опубликованных карточек сверка должна выполняться сама. Черновик от этого не публикуется.

Состояния показываются раздельно: «характеристики собраны» и «страница проверена и обновлена». При неизвестной модификации требуется уточнение исходных данных, а при исчерпанных повторах — разбор указанной ошибки. Это целевой сценарий подготовленного кода; в рабочей CRM он пока не установлен. Пошаговые скриншоты актуального интерфейса входят в незакрытые проверки Gate B.

## Текущие ограничения

Нет доступа к текущим процессам PythonAnywhere, журналам, рабочей БД и точным файлам сервера. Поэтому последний процесс, удаливший раздел, ещё не установлен. Подготовлен инструмент чтения:

```bash
python3 -B runtime_probe.py --root /home/Carix --output /tmp/ua-art-spec-runtime-snapshot.json
```

Команду здесь на сервере не запускали. Скрипт отказывается читать активный WAL/journal и не создаёт «согласованный runtime-снимок» из несогласованных данных. В таком случае нужен отдельно подготовленный согласованный read-only backup и подтверждение путей установленного приложения; выключать CRM для этого по данной задаче не разрешено.

Короткий японский номер кузова распознаётся консервативно и без проверенной связи с каталогом получает NEEDS_REVIEW. Характеристики другой модели автоматически не подставляются. Сохранённые справочные профили имеют ограниченное покрытие; заполнение всех будущих автомобилей нельзя обещать независимо от идентификации и доступности каталогов.

Цели обнаружения до 5 минут и восстановления до 10 минут пока не измерены на сервере. Абсолютная гарантия от произвольной внешней записи файлов невозможна; защита обеспечивается общими проверенными путями публикации, наблюдением и сохранёнными данными. Полноту покрытия путей необходимо доказать перед внедрением.
