# SEO-KOREA-KYIV-001 — исполняемый файл и техническое описание

## Что это
Один самодостаточный файл `seo_korea_kyiv_001.py` без внешних зависимостей, который:

1. В режиме GitHub-раннера (переменная `PYTHONANYWHERE_API_TOKEN` есть, файловая система не `/home/Carix`) — загружает сам себя байт-в-байт на PythonAnywhere через Files API, создаёт ограниченный по времени триггер выполнения через Tasks API, ждёт квитанцию (receipt), удаляет триггер и независимо проверяет публичные URL.
2. В режиме PythonAnywhere (рабочая директория внутри `/home/Carix`) — выполняет полный конвейер:
   `QUEUE → BACKUP → SANDBOX → VALIDATION (Gate A/B) → PRODUCTION (только после PASS) → LIVE VERIFY (Gate C/D) → FINAL REPORT`, с автоматическим байт-в-байт откатом любого изменённого production-пути при провале любого гейта.

## Гарантии безопасности, встроенные в код
- **Динамическая база (baseline)**: количество карточек, VIN, стадии (Kyiv/Georgia/Ferry/Korea) вычисляются сканированием реального `/home/Carix/video` непосредственно перед записью — НЕ хардкодятся как 13 или 16. Если уверенность в базе недостаточна, релиз блокируется (`BASELINE_UNVERIFIED`).
- **Backup**: каждый файл, который будет тронут, копируется в `/home/Carix/archive/backups/SEO-KOREA-KYIV-001_<UTC>/` с SHA-256 до записи; для новых файлов фиксируется факт «до этой задачи не существовал», чтобы откат мог их удалить.
- **Sandbox**: все предполагаемые файлы сначала рендерятся в `/home/Carix/archive/sandbox/SEO-KOREA-KYIV-001_<UTC>/` — до какой-либо записи в production.
- **Gate A (Technical)**: реальные HTTPS-запросs к `/robots.txt`, `/sitemap.xml`, `/`. Если публичный `/robots.txt` не отвечает 200, либо не найден безопасный локальный файл, соответствующий корню сайта (учитывая, что `/` редиректит на `/video/index.html`), релиз БЛОКИРУЕТСЯ с точной причиной — код НЕ угадывает и не правит WSGI/роутинг.
- **Gate B (Content)**: у каждой новой SEO-страницы проверяется единственный `<h1>`, `<title>`, self-canonical, отсутствие смешивания RU/UA на одном URL.
- **Gate C (Regression)**: после записи повторно считается baseline; блокирует релиз и запускает откат, если изменились card_count, stage_counts, набор VIN или хэш любого файла, не входящего в список намеренно изменяемых.
- **Gate D (Live)**: после записи каждый новый канонический URL проверяется реальным HTTP-запросом на статус 200.
- **Rollback**: побайтовое восстановление изменённых файлов из backup + удаление файлов, которых не было до задачи; результат фиксируется в отчёте.
- Никогда не трогает VIN, цены, пробеги, фото/видео, диагностику, стадии, CRM, бот-логику, вёрстку карточек — единственные новые пути — это `/home/Carix/video/seo/ru/*.html`, `/home/Carix/video/seo/ua/*.html` и `/home/Carix/video/sitemap.xml`.

## Важное ограничение текущей поставки
Этот файл **подготовлен и статически проверен по структуре кода**, но **не был запущен против живого продакшна** в рамках данной задачи — запуск на GitHub-раннере и на PythonAnywhere выполняется отдельным шагом ревью/триггера согласно тексту задачи ("GitHub-side triggering/review will be handled separately after code review"). Никакие production-файлы не изменены, никакие сети/CRM/сайт не тронуты этим ответом.

## Известный технический риск, зафиксированный заранее
Публичный корень `/` редиректит на `/video/index.html`. Если сервер не отдаёт `/home/Carix/robots.txt` как публичный `/robots.txt`, Gate A заблокирует релиз и напишет точную причину в финальном отчёте вместо того, чтобы менять WSGI/роутинг без доказательств.
