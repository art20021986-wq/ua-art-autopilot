# CRM-CARD-DELETE-001 — удаление карточки без расхождения сайта и CRM

## Причина (доказано пробами CRM-DELETE-PROBE-20261011 и -R2)
- `cars_ui.delete_ok` удалял строку `cars`, но не обновлял каталог сайта.
  UA-0008 удалена из CRM, но осталась в `katalog.html`.
- `cars_list` сверяет каталог с CRM и при расхождении отказывает
  (`CatalogSnapshotError`) → «Не удалось обновить список» (лог 2026-10-11 13:17).

## Исправление
- `ua_card_delete.py` — новый модуль с одной задачей: порядок удаления.
  Опубликованную карточку сначала снимает с публикации и пересобирает каталог
  существующим `publikaciya.obnovit_katalog` (тот же путь, что «Скрыть от
  клиентов»); при сбое возвращает публикацию и отменяет удаление. Затем
  удаляет строку и пишет audit. Повторное нажатие безвредно.
- `build_cars_ui.py` — заменяет только `delete_ok` в точной установленной
  версии `cars_ui.py` (sha256 fed3ccd1…) на тонкий обработчик.
- Только стандартная библиотека. 7 тестов.

## Установка (нужно «да» владельца)
1. Бэкап, установка `ua_card_delete.py` + собранного `cars_ui.py`, перезапуск бота.
2. Однократно `publikaciya.obnovit_katalog()` — уберёт UA-0008 из каталога.
3. Проверка: каталог = опубликованные карточки CRM, остальные карточки без изменений,
   раздел «Автомобили» открывается.

## Не входит (можно предложить отдельно)
- Фото/медиа удалённых карточек остаются в таблице `media` (связей нет).
- Страница UA-0008.html остаётся на сервере без ссылки из каталога (как при «Скрыть»).
- `cars_list` целиком отказывает при любом расхождении — можно показывать
  список с предупреждением.
