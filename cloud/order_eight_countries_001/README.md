# Авто под заказ: восемь направлений, 40 позиций, одна папка CRM

Спецификация: **UA-ART-ORDER-8COUNTRIES-40-001 v1.1**, 27.09.2026.
Команда владельца «Запускай» разрешает реализацию. Повторное разрешение на
подготовку и тестирование не требуется. Production: после Gate B и отдельной
команды владельца, как установлено в согласованном ТЗ.

**Статус: кандидат подготовлен и локально проверен; к рабочим ботам/WSGI
не подключён, на сайт не установлен. Gate B не пройден.**

## Что подготовлено

- Один расширенный справочник `../ua_order_ge_8country_guard_016/country_models.json`:
  Корея, Япония, Америка (США), Европа, Китай, Канада, ОАЭ, Грузия; по пять
  согласованных позиций. США и ОАЭ имеют независимые массивы.
- 35 локальных фотографий для 40 назначений, восемь отдельных SVG-флагов.
  Модели/категория и фотографии проверены визуально; источники, авторы и
  лицензии сохранены. Фотографии являются иллюстрациями моделей, не записями
  товарного остатка. Раритеты иллюстрирует Mercedes-Benz 230E 1988 года.
- Страница подбора: 4×2 страны, пять карточек внутри страны, отдельный выбор
  «Другая модель», формы/проверка данных/подтверждение, uk/ru/ka. На узких
  экранах карточки предусмотрены по одной в строке, фото слева.
- Независимый от интерфейса контракт `ua_order_request.v1`, SQLite-хранилище
  `order_requests.db`, квитанция после commit, UNIQUE request_id, конфликт
  изменённого тела, серверные события, короткие транзакции и outbox.
- Старые `z_country_bN_kN` и `{t,s,b,k,m,mo,txt}` превращаются в черновик.
  Legacy-данные сами по себе не дают ложного сообщения о сохранении.
- Перенос полного проверенного черновика в Telegram: случайный короткий
  идентификатор, 30 минут, привязка к первому проверенному Telegram user.
- Адаптеры существующей python-telegram-bot: клиентский сценарий и **одна
  папка «Авто под заказ»** со списком «имя · страна», страницами по 20
  заявок и открытием деталей. Нет вложенных папок стран или моделей.
- WSGI-адаптер для существующего приложения; отдельный процесс не требуется.
  Проверяется Origin/CSRF, подпись Mini App, размер/поля JSON и владение
  квитанцией. Ограничитель запросов и текст согласия явно передаёт хост.

Реализация не импортирует cars, CRM DB, VIN, AI, спецификации или publisher.
Записи cars/clients не создаются и не изменяются. Номер заявки не даёт
публичного доступа к её контактам.

## Разделение модулей

| Модуль | Ответственность |
|---|---|
| `ua_order/catalog.py` | Проверенный снимок общего справочника |
| `ua_order/contract.py` | Проверка и нормализация данных |
| `ua_order/repository.py` | Изолированные транзакции и чтение заявок |
| `ua_order/service.py` | Общий приём заявки и серверная идентичность |
| `ua_order/legacy.py` | Совместимые черновики старых входов |
| `ua_order/auth.py` | Подпись Telegram, web-сессия и CSRF |
| `ua_order/web.py` | WSGI-маршруты и подключение к существующей цепочке |
| `ua_order/bot_flow.py` | Состояния клиентского диалога |
| `ua_order/telegram.py` | Адаптер уже используемой библиотеки Telegram |
| `ua_order/crm.py` | Плоский список и отображение заявки |
| `ua_order/notifications.py` | Одна операция существующей очереди уведомлений |
| `web/` | HTML, обычный CSS/JS, локальные медиа |
| `build.py` | Локальная сборка из точного текущего публичного HTML |

Новых production-библиотек нет. Backend использует стандартную библиотеку
Python и уже существующую python-telegram-bot. Для локальной проверки адаптера
использована PTB 22.8 в отдельной тестовой директории, без реальных Telegram
запросов. Версию библиотеки на сервере ещё нужно подтвердить.

## Подключение после получения полных текущих исходников

1. Прочитать целиком текущие lead_bot.py, team_bot.py, WSGI и функции
   авторизации/уведомлений/ограничения запросов. Зафиксировать SHA256, версии,
   реальный путь источника HTML и свежий состав защищённого инвентаря.
2. Создать экземпляры Catalog → Repository → OrderService. Инициализировать
   только явно выбранный приватный `order_requests.db` вне публичной статики.
   Не передавать crm.db и не восстанавливать старую DB поверх новых заявок.
3. Передать WebAdapter существующие origin, rate limiter, проверенный текст
   согласия uk/ru/ka и его версию, серверный secret и текущий токен клиентского
   бота без записи секретов в репозиторий. Подключить `web.mount(application,
   adapter)` внешним слоем WSGI, сохраняя прежнюю цепочку для других маршрутов.
4. В клиентском Application зарегистрировать CustomerAdapter в проверенной
   свободной группе до старых обработчиков. Текущую кнопку заказа направить
   на `order:open`; /order и совместимые /start обрабатываются адаптером.
   Используется последовательная обработка обновлений; настройки другого
   кода не переключать автоматически.
5. В меню CRM добавить одну строку кнопки `crm.FOLDER_LABEL`, callback
   `orders:list`, для существующих разрешённых ролей. Зарегистрировать
   CRMAdapter с текущей функцией авторизации; каждая операция снова проверяет
   роль. Не заменять меню автомобилей, клиентов и этапов.
6. Подключить `notifications.dispatch_once` к существующему job queue и
   существующей отправке менеджеру. Сетевые отправки идут после транзакции.
   После неоднозначного сетевого сбоя уведомление может повториться, всегда
   с тем же номером; новая заявка не создаётся.
7. Собрать preview, проверить реальные iPhone Safari/Chrome, Telegram
   iOS/Android, язык ka носителем и сохранность инвентаря. Затем подготовить
   точный installation manifest, backup, Gate B и откат кода.

Это инструкция интеграции, **не выполненные production-операции**. Нет
установщика, launch marker, автоматического merge или отложенного запуска.

## Локальная проверка

Из корня репозитория:

```sh
PYTHONPATH=cloud/order_eight_countries_001 python -m unittest discover -s cloud/order_eight_countries_001/tests -v
node cloud/order_eight_countries_001/tests/test_web_state.mjs
PYTHONPATH=cloud/ua_order_ge_8country_guard_016 python -m unittest test_sandbox_executor.TestCountryModelsConfig -v
```

Первая команда требует уже используемую PTB в тестовом окружении. При
отсутствии библиотеки интеграционные тесты должны завершиться ошибкой,
а не пропускаться и называться PASS.

Проверены 31 новый Python-тест и пять существующих проверок справочника.
JS-проверки покрывают 24 сочетания страны/языка и сценарии неизвестного
маршрута, сохранения независимых полей и сборки контракта. В их числе:
10 параллельных повторов → одна заявка/одна outbox-строка; повтор после
потери ответа и перезапуска; rollback при ошибке outbox; повтор Telegram
event; чужая квитанция; срок/владение handoff; устаревшее меню; восстановление
квитанции после перезапуска бота; запрет чтения CRM без авторизации.

HTTP-интерфейс проверен локально через WSGI; вызовы Telegram в тестах
подменены запрещающим сеть transport. Это **не живая Telegram-приёмка**.

Пример локальной сборки из предварительно полученных публичных исходников:

```sh
python cloud/order_eight_countries_001/build.py --output /path/to/new/preview --homepage /path/to/current/index.html --podbor /path/to/current/podbor.html
```

Сборка не меняет исходники: заменяет только блок стран и старую форму
в локальных копиях, добавляет ресурсы и сохраняет файловый manifest.
Неизвестная структура формы останавливает сборку.

## Оставшиеся ограничения

- Текущие runtime-файлы ботов не получены полностью: чтение редактора/консоли
  через браузер ограничилось видимыми строками и timeout. Рабочие обработчики,
  схема прежнего приёма, consent/rate limiter и роль не подменены предположениями.
- Подтверждена WSGI-конфигурация PythonAnywhere: Python 3.10, источник
  `/home/Carix/mysite`, цепочка с analitika_wsgi и uaart_bridge_wsgi;
  `/video/` — статическая папка. Само копирование HTML не создаёт HTTP API.
- Прежняя транзакция CRM-PUBLISH-VIDEO-INSTALL-20260927-R4 завершилась
  **ROLLED_BACK**. Это проверено по main d982d034eb425cb805468ed020e9764c387f7446;
  прежний статус ROLLING_BACK больше не используется как текущий блокер.
- Браузер не разрешил локальный сервер preview (EPERM) и file://-предпросмотр
  (политика URL). Визуальная/мобильная приёмка интерфейса **NOT_RUN**; обход
  этих ограничений не выполнялся. Фото как локальные изображения просмотрены.
- Production backup, фактический baseline инвентаря, exact-source integration,
  test-target Python 3.10, отправка клиент → CRM и живой rollback не выполнены.

Откат при будущем выпуске возвращает код/ресурсы. Хранилище заявок и новые
строки не удаляются. При проблемах сначала отключается новый приём, затем
возвращается совместимый обработчик; старую базу поверх новой не копировать.
