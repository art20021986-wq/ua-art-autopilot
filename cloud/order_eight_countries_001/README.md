# Авто под заказ: восемь направлений, 40 позиций, одна папка CRM

Спецификация: **UA-ART-ORDER-8COUNTRIES-40-001 v1.1**, 27.09.2026.
Команда владельца «Запускай» разрешает реализацию. Повторное разрешение на
подготовку и тестирование не требуется. Production: после Gate B и отдельной
команды владельца, как установлено в согласованном ТЗ.

**Статус: кандидат подготовлен и локально проверен; к рабочим ботам/WSGI
не подключён, на сайт не установлен. Gate B не пройден.**

## Что подготовлено

- Один расширенный справочник `../ua_order_ge_8country_guard_016/country_models.json`:
  Корея, Япония, Америка (США), Европа, Китай, Канада, ОАЭ, Грузия; по пять
  согласованных позиций. США и ОАЭ имеют независимые массивы.
- 35 локальных фотографий для 40 назначений, восемь отдельных SVG-флагов.
  Модели/категория и фотографии проверены визуально; источники, авторы и
  лицензии сохранены. Фотографии являются иллюстрациями моделей, не записями
  товарного остатка. Раритеты иллюстрирует Mercedes-Benz 230E 1988 года.
- Страница подбора: 4×2 страны, пять карточек внутри страны, отдельный выбор
  «Другая модель», формы/проверка данных/подтверждение, uk/ru/ka. На узких
  экранах карточки предусмотрены по одной в строке, фото слева.
- Независимый от интерфейса контракт `ua_order_request.v1`, SQLite-хранилище
  `order_requests.db`, квитанция после commit, UNIQUE request_id, конфликт
  изменённого тела, серверные события, короткие транзакции и outbox.
- Старые `z_country_bN_kN` и `{t,s,b,k,m,mo,txt}` превращаются в черновик.
  Legacy-данные сами по себе не дают ложного сообщения о сохранении.
- Перенос полного проверенного черновика в Telegram: случайный короткий
  идентификатор, 30 минут, привязка к первому проверенному Telegram user.
- Адаптеры существующей python-telegram-bot: клиентский сценарий и **одна
  папка «Авто под заказ»** со списком «имя · страна», страницами по 20
  заявок и открытием деталей. Нет вложенных папок стран или моделей.
- WSGI-адаптер для существующего приложения; отдельный процесс не требуется.
  Проверяется Origin/CSRF, подпись Mini App, размер/поля JSON и владение
  квитанцией. Текст согласия загружается из приватной конфигурации. Локальный ограничитель
  защищает новые запросы, не меняя действующие экраны.

Реализация не импортирует cars, CRM DB, VIN, AI, спецификации или publisher.
Записи cars/clients не создаются и не изменяются. Номер заявки не даёт
публичного доступа к её контактам.

## Точное подключение подготовлено

Полностью прочитаны текущие `lead_bot.py`, `client_ui.py`, `team_bot.py` и WSGI.
`integrate.py` проверяет четыре исходных SHA256, формирует приватные копии с
минимальными вставками и diff. Любое расхождение источника останавливает сборку.

```sh
python cloud/order_eight_countries_001/integrate.py --sources /path/to/current/private/sources --output /path/to/new/private/candidate
```

Изменяются только:

1. **lead_bot:** регистрация после `handlers.clear()` и `client_ui.register`,
   перед последним `return app`. Новая группа выбирается раньше всех текущих.
2. **client_ui:** подпись одной кнопки. Все действующие входы `c_order`, `c_ans:`,
   `lead_start`, `buycar:`, `ready`, `custom_order` перехватываются адаптером.
   Старые незавершённые кнопки анкеты открывают новый выбор страны. Переходы
   в каталог, карточку, бронь, вопрос, условия, контакты и главное меню очищают
   только состояние новой анкеты и передают управление действующему экрану.
3. **team_bot:** одна кнопка папки и одна регистрация перед возвратом приложения.
   `who(update)` и активная роль owner/admin/manager проверяются при каждом чтении,
   только в личном чате. Доставка использует существующий CRM job queue и бот,
   действующих менеджеров, при их отсутствии — действующих владельцев.
4. **WSGI:** финальная обёртка только для `/api/orders/`, снаружи аналитики,
   bridge, SEO и актуального `uaart_public_prices_v1`. Прочие маршруты делегируются.

Обработчик старого inbox не вызывается с номером заказа: у него другой тип записи
и callback. Заказ получает собственный `orders:open:<id>`. Уведомления отправляются
после commit; успешная доставка каждому адресату сохраняется отдельно. Ошибка
одного адресата не блокирует остальных и не повторяет уже подтверждённые доставки.
Неоднозначный сетевой сбой допускает повтор с тем же номером. Повторы ошибок имеют
увеличивающийся интервал до одного часа; заявки не удаляются.

`settings.example.json` выключен и не содержит выдуманного согласия или секретов.
Хост читает `/home/Carix/order_requests/settings.json` либо явный `UA_ORDER_SETTINGS`.
Пакет `ua_order` должен быть в существующем пути импорта `/home/Carix`; каталог и
строки задаются точными приватными путями, ресурсы — `/home/Carix/video/order`.
До включения отдельно инициализируется **только** `order_requests.db`, создаётся
приватный `session.key` (не менее 32 случайных байт) и передаётся утверждённое
согласие uk/ru/ka с версией. Runtime сам не создаёт базу, ключи или миграции.

В текущих проверенных обработчиках ограничитель частоты не найден. Новый небольшой
лимитер использует стандартную библиотеку: 10 web-попыток на сессию/минуту,
60 на серверный REMOTE_ADDR/минуту, 60 Telegram-обновлений на пользователя/минуту.
Каждый лимитер ограничен 4096 активными ключами. Это **лимит одного процесса**,
не глобальный лимит между WSGI workers; он не заменяет уникальность заявки в БД.

Отсутствующая/выключенная конфигурация сохраняет старое поведение. Некорректная
включённая конфигурация блокирует новый приём: API возвращает 503, бот сообщает
о временной недоступности. Существующие сайт, каталог и CRM продолжают работать.

Это подготовленный локальный патч, **не установка на сервер**. Автоматического
merge, launch marker, перезагрузки или отложенного production-запуска нет.

## Локальная проверка

Из корня репозитория:

```sh
PYTHONPATH=cloud/order_eight_countries_001 python -m unittest discover -s cloud/order_eight_countries_001/tests -v
node cloud/order_eight_countries_001/tests/test_web_state.mjs
PYTHONPATH=cloud/ua_order_ge_8country_guard_016 python -m unittest test_sandbox_executor.TestCountryModelsConfig -v
```

Первая команда требует уже используемую PTB в тестовом окружении. При
отсутствии библиотеки интеграционные тесты должны завершиться ошибкой,
а не пропускаться и называться PASS.

Проверены 42 новых Python-теста и пять существующих проверок справочника.
JS-проверки покрывают 24 сочетания страны/языка и сценарии неизвестного
маршрута, сохранения независимых полей и сборки контракта. В их числе:
10 параллельных повторов → одна заявка/одна outbox-строка; повтор после
потери ответа и перезапуска; rollback при ошибке outbox; повтор Telegram
event; чужая квитанция; срок/владение handoff; устаревшее меню; восстановление
квитанции после перезапуска бота; запрет чтения CRM без авторизации.

Отдельная сквозная проверка проходит через HTTP handoff → клиентский адаптер
бота → подтверждение → плоскую папку CRM → детали → outbox. Повтор подтверждения
оставляет одну заявку и одно уведомление; модель, комментарий и контакт сохранены.

Дополнительно проверены реальные группы диспетчера PTB, старые кнопки и выходы
из анкеты, отказ одного получателя, отсутствие повторов успешному получателю,
изоляция ошибки конфигурации, ограничитель и отказ SQLite на сетевой ФС.

Проверка приватных текущих исходников выполняется отдельно и не пропускается:

```sh
PYTHONPATH=cloud/order_eight_countries_001 python cloud/order_eight_countries_001/tests/check_host_sources.py --sources /path/to/current/private/sources
```

Она подтверждает четыре SHA, отказ при изменении источника, неизменность 294
посторонних узлов Python AST, реальную регистрацию client_ui и сохранность
остальных кнопок CRM для всех трёх ролей. Runtime-модули целиком не импортируются,
секреты и рабочие базы не открываются.

HTTP-интерфейс проверен локально через WSGI; вызовы Telegram в тестах
подменены запрещающим сеть transport. Это **не живая Telegram-приёмка**.

Пример локальной сборки из предварительно полученных публичных исходников:

```sh
python cloud/order_eight_countries_001/build.py --output /path/to/new/preview --homepage /path/to/current/index.html --podbor /path/to/current/podbor.html
```

Сборка не меняет исходники: заменяет только блок стран и старую форму
в локальных копиях, добавляет ресурсы и сохраняет файловый manifest.
Неизвестная структура формы останавливает сборку.

## Оставшиеся ограничения выпуска

- Утверждённый текст согласия компании не найден в прочитанных клиентских
  обработчиках и публичной форме. Пустые или тестовые тексты не выдаются за
  утверждённые; production-конфигурация не включалась.
- SQLite WAL требует общей памяти на одном хосте. PythonAnywhere документирует
  сетевую файловую систему и проблемы SQLite при нескольких процессах. Кандидат
  подходит для проверенного локального хранилища, **не признан пригодным для
  общей БД WSGI и bot task на PythonAnywhere**. Runtime отклоняет NFS/CIFS и
  другие распознанные сетевые ФС. Это блокер выпуска, не решённый сменой PRAGMA.
  Проверка страницы существующих серверных БД 27.09 дважды вернула HTTP 502.
  Альтернатива для согласования: существующий MySQL/PostgreSQL, если доступен;
  миграция CRM и новый внешний сервис в эту задачу не добавлены.
- Версия PTB на сервере и исполнение на Python 3.10 не проверены; локальные
  адаптеры проверены на PTB 22.8/Python 3.12, синтаксис — для Python 3.10.
- Браузер не разрешил локальный preview (EPERM) и file://. Мобильная/визуальная
  приёмка **NOT_RUN**. Эти ограничения не обходились; локальные фото просмотрены.
- Production backup, актуальный baseline инвентаря, живой маршрут Telegram,
  установка и откат не выполнялись. Gate B остаётся **NOT_PASSED**.
- По проверенному main `6745ea17e43d65c46feaa225c57a649f787fcd35` прежний
  CRM publisher R4 откатан, последующий R5 завершён. Незавершённый откат больше
  не указывается блокером этой задачи. Чужие исправления не меняются.

Откат при будущем выпуске возвращает код/ресурсы. Хранилище заявок и новые
строки не удаляются. При проблемах сначала отключается новый приём, затем
возвращается совместимый обработчик; старую базу поверх новой не копировать.
