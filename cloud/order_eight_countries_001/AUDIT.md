# Аудит сценария «Авто под заказ»

Дата: 27.09.2026. Объём: публичная главная страница, публичная форма подбора,
доступная конфигурация хостинга и подготовленный кандидат. Реальных заявок
клиентам/менеджерам в ходе проверки не отправляли.

## Как работает сейчас — подтверждённые факты

| Часть | Наблюдение | Последствие для изменения |
|---|---|---|
| Главная `/video/index.html` | В `.countries-inline` пять неактивных обозначений стран; рядом общий переход к подбору | Подготовлены восемь настоящих ссылок с кодом страны и языком |
| `/video/podbor.html` | Пять направлений: Корея, Япония, США, Европа, Китай; по пять моделей, без фотографий в этом выборе | Общий справочник расширен до восьми направлений и 40 позиций |
| Вход без страны | Текущий скрипт использует Корею по умолчанию | Кандидат показывает выбор страны, неизвестный код не превращается в другую страну |
| Поля старой формы | Бюджет, модель или другая модель, тип автомобиля, свободное описание | Совместимость разбирает прежние значения в черновик и сохраняет комментарий отдельно |
| Telegram Web App | Формируется `{t,s,b,k,m,mo,txt}`; при выполненном `sendData()` интерфейс сразу показывает «Заявка принята» | Эта надпись подтверждает вызов клиентского метода, но не доказывает запись на сервере. Кандидат показывает квитанцию после commit |
| Вход в бот из обычного браузера | Ссылка `start=z_<страна>[_bN][_kN]` содержит страну, бюджет и тип; модель/комментарий не включены | Кандидат передаёт полный черновик через короткий серверный идентификатор |
| WhatsApp | Формируется текст заявки; отдельно можно открыть чат для передачи фото | В новом сценарии ссылка после сохранения содержит номер заявки |
| Веб-хостинг | PythonAnywhere, Python 3.10, source `/home/Carix/mysite`; `/video/` обслуживается как статика; WSGI включает обёртки analitika_wsgi и uaart_bridge_wsgi | Для приёма заявок нужен явный WSGI mount; копирования HTML недостаточно |

Источники: свежие публичные HTML страницы `https://www.uaart.com.ua/video/index.html`
и `https://www.uaart.com.ua/video/podbor.html`, а также прочитанная конфигурация
PythonAnywhere. SHA256 полученных HTML фиксируется в `verification.json`.
Полные приватные runtime-файлы и содержимое клиентских баз в этот пакет не включены.

## Текущий клиентский бот: подтверждённая цепочка

27.09.2026 в 10:46:28 UTC получен полный `lead_bot.py` через авторизованное
текстовое представление PythonAnywhere: 100 314 байт, AST PASS, SHA256
`27270e38f1b7ed913140127231149b6d862876f3b3a02a58c4a852b40ce8a3f8`.
Этот SHA также совпадает с protected hash в ранее выполненном серверном
preflight CRM-PHOTO-INTAKE-PREFLIGHT-20260927 от 08:31 UTC. Сам приватный
исходник в публичный репозиторий не включён.

Фактический порядок внутри `build_application`:

1. Создаётся PTB Application и регистрируются прежние диалоги.
2. `app.handlers.clear()` удаляет все эти обработчики.
3. Добавляется временный `/start`.
4. Вызывается `client_ui.register(app, MANAGER_CHAT_ID)`; предусмотрен старый
   вариант вызова без chat_id.
5. Приложение возвращается вызывающему коду.

Новый адаптер следует регистрировать после шага 4. Регистрация до очистки
будет потеряна. Порядок групп требует проверки текущего client_ui. Старые jobs
планировщика очисткой обработчиков не удаляются; эта задача их не меняет.

В lead_bot.py присутствуют прежние функции JSON-сохранения, отражения заявки
в CRM и уведомления менеджера. Они не доказывают поведение актуальной анкеты,
поскольку её обработчики подключаются из client_ui. Явного текста согласия и
ограничителя частоты в lead_bot.py не найдено; на непрочитанный client_ui этот
вывод не распространяется.

## Что остаётся неподтверждённым

Текущий `client_ui.py`, текущий `team_bot.py` и полный актуальный WSGI через
доступный браузер прочитать не удалось: raw-входы вернули ERR_BLOCKED_BY_CLIENT;
проверка вкладки WSGI также получила явный отказ политики безопасности.
Обходов ограничений не выполняли. Поэтому не подтверждены:

- фактические обработчики всех прежних входов, свободные группы PTB и её версия;
- порядок сохранения заявки и уведомления в текущем клиентском боте;
- действующие функции проверки ролей, ограничения запросов и согласия;
- текущая внутренняя раскладка CRM и полный маршрут «клиент → менеджер».

Имеются только опорные локальные копии: client_ui из архива от 05.09,
team_bot с SHA `aebe2c091fdf1f19a8a011784dd70e2d648dc04607ec64374e4ff9f402e995af`
(совпадает с серверным preflight от 08:31 UTC) и WSGI от 21.09. Они помогают
подготовке, но не заменяют проверку точных исходников непосредственно перед выпуском.

Это частичный аудит, а не отметка о полной проверке production. Подготовленные
адаптеры не подключены к текущим ботам и не подменяют отсутствующие сведения.

## Как работает подготовленный кандидат

| Интерфейс | Сценарий |
|---|---|
| Сайт | Страна → пять моделей с фото либо другая модель → параметры/доставка/контакт → проверка данных и согласие → сохранение и номер |
| Клиентский бот | Страна → пять моделей → фото выбранной модели → параметры/доставка/контакт → проверка данных и согласие → сохранение и номер |
| Переход сайт → бот | Проверенный полный черновик хранится 30 минут; случайный идентификатор привязывается к первому проверенному Telegram-пользователю |
| CRM-бот | Одна папка **«Авто под заказ»** → плоский список **«имя клиента · страна»** → детали заявки; без вложенных папок моделей/стран и без каталога фото |
| Общая запись | Одна изолированная база заявок; повтор одной отправки возвращает прежний номер; уведомление менеджеру поставлено в outbox той же транзакцией |

Направления: Корея, Япония, Америка (США), Европа, Китай, Канада, ОАЭ, Грузия.
«Европа» — согласованное название направления закупки.

Локально проверены контракт, повторы/конкуренция, подписи/права, совместимые
черновики, состояния бота, плоский список CRM и ограниченное преобразование
HTML. Дополнительно пройден маршрут HTTP handoff → клиентский адаптер бота →
подтверждение → плоский список CRM → детали → outbox, с сохранением всех полей
и одной заявкой при повторе. Нативная библиотека PTB проверена с транспортом,
запрещающим сеть. В сквозном тесте отправка сообщений заменена локальными mocks.

Визуальная проверка сайта в браузере, мобильная проверка, целевой Python 3.10,
живой Telegram и сохранность фактического инвентаря после установки ещё не
проверены. Локальный preview был заблокирован средой; ограничение не обходили.

статус **ROLLED_BACK** на проверенном main `d982d034eb425cb805468ed020e9764c387f7446`;

в `README.md`. Отдельные изменения производительности CRM и другие улучшения
не входят в эту работу.
