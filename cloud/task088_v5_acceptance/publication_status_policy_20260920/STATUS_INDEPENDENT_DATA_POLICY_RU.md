# Независимость данных объявления от статуса публикации

Дата: 20 сентября 2026 года. Основание: уточнение владельца в текущем диалоге.
Статус: обязательное требование; реализация переходов между статусами ещё не принята.
Проверенный исходный кандидат: `444b0c7fc6359629b2a3983fbc539d1939b2b38c`.

## Правило

Каждое объявление CRM получает одинаковые гарантии сохранения, проверки, восстановления и защиты новых изменений оператора независимо от публикации. Флаг публикации определяет доступность объявления посетителям сайта. Он не исключает запись из обработки данных и не требует отдельного разрешения на каждое объявление.

Правило относится к существующим разрешённым операциям с ценами UA/GE, характеристиками и медиа. Оно не расширяет права операторов, не публикует черновики автоматически и не превращает ценовой worker в произвольный редактор данных.

| Состояние | Данные CRM | Публичный сайт |
|---|---|---|
| Не опубликовано | Сохранение, отдельное чтение результата, журнал, защита от дублей и конфликтов | Публичные страницы не создаются; результат отображения — NOT_APPLICABLE |
| Опубликовано | Те же гарантии данных | Карточка, каталог и применимые разделы получают согласованную версию; существующее требование ≤60 секунд сохраняется для согласованной синхронизации цен UA/GE |
| Публикация | Сначала согласование уже принятых операций и чтение актуальной версии | Штатная публикация создаёт страницы из последних подтверждённых данных |
| Снятие с публикации | Запись, история и исходные медиа сохраняются | Штатный путь закрывает доступ к карточке и убирает объявление из каталога и других обслуживаемых представлений |

Первая публикация остаётся отдельным действием через существующий разрешённый штатный механизм. Изменение цены не является командой публикации.

## Как реализовать без повторения проблемы

1. Стабильный внутренний `car_id` связывает операции и историю для обоих статусов. Неполный черновик может не иметь кода, VIN или цены; проверка готовности публичной карточки выполняется при публикации. Значения не выдумываются, пути из непроверенной идентичности не строятся.
2. Один логический журнал операций охватывает изменения опубликованных и неопубликованных записей. Существующий путь Stage 2 можно сохранить только с совместимыми доказательствами, которые понимают worker и защита пересборки. Старые квитанции неизменны.
3. У операции раздельные результаты: сохранение данных и обновление публичного представления. Для черновика требуется проверенное сохранение плюс наблюдённый статус NOT_APPLICABLE для сайта. Это не Site PASS.
4. Каждая операция связывается с версией данных и версией видимости. Правки и смена статуса упорядочиваются для одного автомобиля; общие страницы обновляются под общей защитой писателей. Прямо перед переключением публичных файлов проверяются актуальная версия видимости и разрешение. Сетевые проверки выполняются вне общей блокировки; перед записью повторно проверяются версия и допуск.
5. Если статус изменился при незавершённой операции, сначала определяется фактическое состояние записи и файлов. Восстановление продолжает тот же идентификатор операции. Сохранённая цена не записывается повторно, старый запрос не открывает объявление заново, новые правки оператора не откатываются.
6. Снятие с публикации получает отдельную проверяемую квитанцию закрытия публичного доступа. Проверяются фактически обслуживаемые URL, зеркала, карточка, каталог и другие существующие публичные представления. Скрытия ссылки из каталога недостаточно. Удаление публичного представления не означает удаление исходных данных или медиа.
7. Защита полной пересборки должна понимать подтверждённые изменения черновиков и завершение переходов видимости. Она сохраняет запрет неподтверждённых записей, но не сравнивает новую законную правку черновика только с устаревшей квитанцией публичной цены. Нельзя стирать журнал или пропускать незавершённые операции ради продолжения.
8. Зависшую операцию обрабатывает ограниченная процедура восстановления с сохранённым исходом и диагностикой. Обход защиты запрещён; разные операции не должны взаимно ждать друг друга из-за несовместимых правил очереди и публикации.

## Текущий состав объявлений и Preview

Проверка данных охватывает все записи CRM. Проверка публичного HTML охватывает текущий опубликованный набор. Количество 18, номера конкретных автомобилей и прежнее распределение по этапам — исторические факты, а не постоянные ограничения.

Изменение состава запускает сравнение снимков и проверку затронутых зависимостей: добавленной/снятой карточки, общих страниц, счётчиков, данных и результата генерации. Неизменные проверки можно зачесть только по совпадающим входам и зависимостям. Старый Preview 24/24 не становится текущим автоматически.

Если состав изменился после подготовки установки, старый пакет не запускается: сохраняется новый снимок, согласуется фактический исход других операций, обновляются затронутый кандидат и необходимые допуски. Неограниченных повторов нет. Свежие Gate B, контроль писателей, резервная копия и точная привязка кода/схемы остаются обязательными.

Сам статус публикации не является блокером. Конкурирующий писатель, неизвестный исход записи, неоднозначная идентичность и неподтверждённые данные по-прежнему требуют разрешения соответствующей проблемы.

## Найденные незакрытые случаи

**PS-01.** Завершённая публичная правка → снятие с публикации → правка цены черновика → полная пересборка. Черновик сейчас пишет через Stage 2 без новой V5-квитанции; `_task088_price_quiescence` сравнивает цену с прежней V5-квитанцией и может выдать `TASK088_V5_UNTRACKED_CRM_PRICE_CHANGE`.

**PS-02.** Принятая публичная правка ещё не завершена → объявление снято с публикации. Проверки `resolve_identity` / `_full_row` требуют `published=1`, а общая защита запрещает пересборку при любой незавершённой V5-операции. Это создаёт риск постоянной блокировки очереди и общей пересборки.

Оба вывода получены независимым анализом кода; новые сценарии исполнения в этом уточнении не запускались. Простое снятие проверки `published` не решает проблему: текущий worker требует существующие CARD/CATALOG/HOME и может затронуть публичную видимость.

## Обязательные сценарии приёмки

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| PS-A01 | Черновик: UA, GE, пустая GE и неполная идентичность | Данные проверены; черновик не создаёт общедоступных представлений, нет ложного Site PASS |
| PS-A02 | Черновик → публикация → повтор старого сообщения | Нет повторной записи и потери более новой цены |
| PS-A03 | Публичная правка → снятие → правка черновика → пересборка → повторная публикация | PS-01 устранён, текущие данные и история сохранены |
| PS-A04 | Снятие во всех сохранённых состояниях очереди, включая DB_COMMITTED | PS-02 устранён; исход установлен, нет дублей, самопубликации или постоянного ожидания |
| PS-A05 | Публикация при принятых правках черновика | Сохраняется порядок операций и используется последняя подтверждённая версия |
| PS-A06 | Снятие с публикации и оставшаяся старая прямая ссылка | Доступ закрыт на реальных обслуживаемых представлениях; исходные данные и медиа сохранены |
| PS-A07 | Обрыв/перезапуск при смене статуса и более новая правка оператора | Возобновление той же операции; новые данные не перезаписаны |
| PS-A08 | 0, 1, 18, 19 и более опубликованных записей, добавление и снятие | Нет постоянного ограничения числа; верны текущие карточки и счётчики |
| PS-A09 | Опубликованные: Киев, пустая GE, повторные правки UA/GE | Согласованность карточки/каталога за ≤60 секунд, сохранение независимых полей |
| PS-A10 | Изменился состав при подготовке пакета; неизменный код/дизайн | Старый пакет не выполняется; пересчитаны затронутые доказательства, неизменные зачтены по зависимостям |

Эта матрица уточняет существующую приёмку; она не увеличивает её итоговое число 20 и не добавляет зачёт без доказательств. Для новых сценариев статус OPEN. Ранее принятые результаты сохранены в исходных границах.

## Порядок продолжения

Прочитать текущий checkpoint и фактический исход существующей операции UA-0022 без повторного запуска. Подготовить совместимое исправление PS-01/PS-02 в изолированном кандидате; проверить переходы и пройти независимый review. Затем подтвердить актуальную применимость Preview и продолжить обязательные этапы установки. Рабочий сайт и текущая схема БД этим документом не изменяются.
