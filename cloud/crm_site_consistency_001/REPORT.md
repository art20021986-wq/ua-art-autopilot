## Найденные дефекты

1. Предыдущий run 36249087712 получил данные, но не сохранил принятый результат: RECEIPT_MISSING:rollback_ready. Дополнительно target_environment=production_read_only не входит в разрешённые значения неизменённого валидатора. Новый диагностический пакет использует shadow как среду выполнения без записей и отдельно observation_environment=production_read_only как источник чтения. rollback_ready означает отсутствие production-мутации для отката, что прямо указано в rollback_reason. Валидаторы и защитные требования не ослаблялись.
2. Точный установленный ua_public_freshness.py с SHA256 6c750d0ffcfd3959413120905e46b8765049a2a207b77741d7fc5721a225c134 проверял VIN/год и цены, но не остальные характеристики. В изоляции воспроизведено принятие старого пробега 167008 при CRM 167007 и совпадающих публичных байтах. Ценовая зависимость в этом узком тесте заменена заглушкой; живые записи не менялись.
3. Синхронизатор просматривает только published=1 и сравнивает их ревизии с начальным baseline. Это не полная проверка содержимого неизменённых карточек. Прочитанный reconcile_once не содержит обработки исчезнувших из выборки ID. Внешний путь удаления не исследован полностью, поэтому отсутствие удаления во всей системе не утверждается.
4. Начальный отчёт другого исполнителя о старом HTML является исторической гипотезой. Текущие файлы и сохранённый снимок уже содержат актуальные цены. Диагноз «всё из-за кэша» этими проверками не подтверждён.

## Кандидат и проверки

`public_fields.py` — чистый проверяющий модуль без I/O. `freshness.patch` добавляет его вызов в существующий проверяющий путь. `build_candidate.py` принимает только точный исходник с указанным SHA256; полный частный исходник в репозиторий не включён. Установка не выполнена.

Проверки: 12 тестов характеристик (включая stale VIN, видимый заголовок, пробег, двигатель, топливо, коробку, привод, цвет и дубли полей) и 6 тестов диагностического пакета, включая принятие квитанции действующим task_orchestrator.validate_receipt. Проверки реальных HTML: 42/42. Контрольные суммы трёх файлов архива GitHub Actions проверены по manifest.

Запуск тестов кандидата требует локального точного частного исходника:

```sh
python3 cloud/crm_site_consistency_001/build_candidate.py /private/ua_public_freshness.py cloud/crm_site_consistency_001/runtime/ua_public_freshness.py
python3 cloud/crm_site_consistency_001/test_public_fields.py
python3 cloud/crm_site_consistency_probe_20260926/test_contract.py
```

## Что ещё не принято

Полный реестр всех публичных полей; фотографии/видео и порядок галереи; описание и допспецификация; языковые DOM после JS; правила archive; весь путь удаления; достоверный статус в интерфейсе бота; уведомления после пяти ошибок; гонки/сбои и SLA 60 секунд; независимая приёмка на iPhone; Gate B, deployment и наблюдение 24 часа.

Проверка текущего снимка не гарантирует автоматического исправления будущих изменений. Общий PASS ТЗ запрещён до закрытия этих пунктов. Следующая диагностическая задача `CRM-SITE-CONSISTENCY-PROBE-20260926` собирает ограниченные свидетельства через GET/HEAD; она не устанавливает кандидат и не выдаёт приёмку всего ТЗ.
