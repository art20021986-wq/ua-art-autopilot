# TASK 078 — CRM-VOICE-WATCHDOG-005 v1.0

## Результат

`PASS_READY_FOR_SEPARATE_PRODUCTION_APPROVAL`

Причина зависания подтверждена свежим GET-аудитом live-кода: для любого
голосового использовался общий дедлайн 4,65 секунды, а `ai.transcribe`
запускался через неубиваемый `asyncio.to_thread`. После timeout поток мог
продолжать работать и накапливать зависшие расшифровки.

## Канонический кандидат Gate B

- `voice_watchdog.py` — отдельный killable STT process group, `TERM` → 3 с →
  `KILL`, одна автоматическая повторная попытка, максимум два параллельных
  worker-а, timeout по длительности голосового и общий restart budget.
- `handler_patcher.py` — fail-closed патчер точного live SHA; меняет только
  голосовой блок `cars_ui.catch_message`, сохраняет существующую CAS-запись и
  idempotency marker, освобождает marker при неуспехе и показывает кнопку
  «Повторить голосовое».
- `live_audit.py` — только GET; собирает и компилирует реальный кандидат в
  памяти, не записывая его в production.
- `tests/test_voice_watchdog.py` и `tests/test_handler_patcher.py` — основные
  тесты канонического кандидата.

Остальные ранние модули в этой папке являются справочным sandbox-каркасом и
не входят в установочный набор Gate B.

## Ограничение безопасности

Перезапуск всего Telegram-процесса в кандидате запрещён: live-аудит показал,
что текущий supervisor не обрабатывает exit code 75. Перезапускается только
зависший STT-worker, поэтому текст, фото и кнопки остаются доступны.

Production, CRM и процессы не изменялись. Установка и контролируемый рестарт
бота требуют отдельной письменной команды владельца.
