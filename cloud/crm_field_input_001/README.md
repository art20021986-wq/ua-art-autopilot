# CRM-FIELD-INPUT-001 — ссылка OBD/УБД и другие поля не сохраняются после загрузки файлов

## Причина (доказано пробой CRM-DIAG-LINK-PROBE-20261012, исходники cars_ui.py sha 5da4d9e8…)
- «Добавить фото/видео» ставит ожидание файлов `car_media_wait`.
- Кнопка поля (`edit_ask`, напр. «Ссылка OBD», «Описание») ставит `car_wait`,
  но ожидание файлов не снимает.
- `catch_message` сначала проверяет `car_media_wait`; на обычный текст просто
  выходит, и сообщение уходит в `team_bot.intake` → `run_ai_draft` →
  «Поля CRM не распознаны». На скриншоте владельца перед этим видно
  «Сохранено. Всего: 1 из 10» — сначала было загружено видео проверки.
- Касается любого поля любой карточки, а также полей покупателя (`client_ask`).

## Исправление (одна правка, один файл)
`build_cars_ui.py` в точной установленной версии `cars_ui.py`:
- добавляет помощник `_ua_wait_text`: новый запрос значения отменяет прежние
  ожидания ввода (файлы, контейнер `cont_wait`, характеристика `ua099_spec_edit`) —
  тот же приём уже используют `drop_wait` и `konteyner._sprosit`;
- в `edit_ask` и `client_ask` меняет по одной строке установки `car_wait`
  на вызов помощника. Остальной код не трогается.
- Только стандартная библиотека. 4 теста (включая воспроизведение ошибки).

## Установка — ждёт «да» владельца
Пакет развёртывания по образцу `cloud/crm_card_delete_002`: бэкап, замена одного
`cars_ui.py`, перезапуск бота, проверка хэшей, CRM и сайт не меняются.

## Не входит (можно предложить отдельно)
- Заголовок запроса показывает техническое имя `diag_link` / `diag_text`
  вместо «Ссылка OBD» / «Описание» (их нет в списке названий `EDITABLE`).
