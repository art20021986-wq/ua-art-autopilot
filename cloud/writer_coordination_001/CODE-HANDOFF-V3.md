# Исправление server STORAGE_PREFLIGHT и handoff v3

Фактический запуск v2 на PythonAnywhere завершился 23 тестами, 11 ошибками и 3 несовпавшими ожидаемыми исключениями. Все 14 неуспешных случаев имеют одну причину `STORAGE_PREFLIGHT`. Запретов IO/network — 0; файлы комплекта неизменны. Протоколы сохранены `evidence/handoff-v2-server-*`, точные исходники — как v2 и в `archive/handoff-v2-server-failed/`.

Ошибка была в установщике: процент заполнения **общей серверной файловой системы** `statvfs` ошибочно трактовался как заполнение оплаченного аккаунта Carix. Это не свидетельство переполнения аккаунта. По отдельному наблюдению владельца маршрута в интерфейсе 9 сентября: 6,8 из 35 GB.

`code_handoff_v3.py` исправляет смысл проверки, сохраняя требования TASK107:

- абсолютных свободных байт общей файловой системы должно хватать;
- независимо подтверждённой свободной квоты аккаунта должно хватать на реальные старые исходники, новый пакет, staging и журнал;
- 70% аккаунта — предупреждение, 80% — запрет большой установки, 90% — emergency STOP;
- неподтверждённая или устаревшая квота не считается разрешением.

При фазе `STORAGE_PREFLIGHT` независимый `verify_window` обязан вернуть `storage_quota`: `source: AUTHENTICATED_PYTHONANYWHERE_ACCOUNT_QUOTA`, целые `used_bytes`/`quota_bytes`, `observed_at` не старше 30 секунд и `receipt_sha256`. Сам JSON не удостоверяет происхождение: реальный upstream проверяющий модуль должен подтвердить источник. Тестовый поставщик квоты существует только в синтетических тестах.
