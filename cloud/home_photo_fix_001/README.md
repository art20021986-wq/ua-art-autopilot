# HOME-PHOTO-FIX — «✅ Поставить на главную» снова работает

Задача: `tasks/HOME-PHOTO-FIX-001.md`.

## Причина (проверено на живой главной 15.11)
С 10.11 модуль Кореи `ua_korea_home.py` (по решению владельца) выносит фото главной из первого экрана
в свой блок `<!--UA-HOME-PHOTO-V1-->` над «Авто в наявності». Публикатор фото `ua_home_photo_site.py`
искал фото только внутри первого экрана (`<section class="hero ua-order-first">…`), не находил
(`SiteError: HOME_PICTURE:0`) и, как и задумано, ничего не менял: «Не получилось поставить фото».

## Исправление
`ua_home_photo_site.py` (замена) — фото ищется по тому, что это за картинка, а не по месту:
единственный простой `<picture>` страницы, чья картинка грузится первой (`fetchpriority="high"`,
её пишет сам модуль). Где бы блок ни стоял — найдётся; нет или две — отказ, страница не меняется.
Остальное без изменений: бэкап `index.html`, атомарная запись, отказ, если страница изменилась
во время записи, тот же CSS-блок `ua-home-photo-001`.

## Проверки
- `test_home_photo_site.py` — на живой копии главной (`fixtures/index_live.html`, 15.11): меняются
  только фото и CSS-блок; фото остаётся в своём блоке; модуль Кореи (`fixtures/ua_korea_home.txt`,
  установленная версия 2549a928) при перезаписи главной CRM оставляет результат как есть; старая
  раскладка (фото в первом экране) тоже работает; нет/два фото — отказ.
- Превью на сервере (`deployment_remote.smoke`): новый и установленный модуль правят живую главную
  в памяти, установленный `ua_korea_home.apply` не меняет результат, причина из журнала бота
  (строки после `home photo: publish failed`). Ничего не пишет.
- Установка по образцу `cloud/order_storage_guard_001`: бэкап, пауза бота, запись одного файла,
  проверка, запуск бота, откат тем же пакетом. Сайт и CRM установка не меняет.
