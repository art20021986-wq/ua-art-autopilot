## Изменение

Сохранение этапа в CRM завершается существующим кодом. После него обработчик
только будит существующий фоновый worker и честно сообщает, что обновление
сайта ещё выполняется. Периодическая stage-задача тоже только будит worker.
Второй независимый цикл публикации и ожидание его блокировки из ответа исчезают.

Worker сохраняет штатные блокировки, резервирование, проверки публикации,
публичную проверку и журнал ревизий. Общая ошибка состава каталога получает
сохраняемый в журнале перерыв 15 минут на неизменных исходных данных. Новая
правка CRM разрешает новую попытку сразу; изменение времени HTML и перезапуск
процесса не обходят перерыв. После его истечения повтор возобновляется.
Обычные временные ошибки сохраняют отдельные попытки по карточкам с интервалом
15, 30, 60, 120, 240, 480, 900 секунд. Другие карточки не блокируются этой
веткой ошибок. Успешное скрытие будит следующую обработку без лишних 15 секунд.

Итоговая сборка содержит три файла: cars_ui.py и publikaciya.py в точности из
stage_edit_recovery_001, затем ua_crm_public_sync.py с контролем повторов.
Сохраняются исправления маршрутизатора старых кнопок и единого списка активных
карточек. Не устанавливать поверх друг друга отдельные варианты cars_ui.py.
Данные CRM, медиа и шаблоны не изменяются сборщиком. Все действительные записи
на сервер будут выполнены только будущей защищённой установкой.

## Проверка

`python3 -m unittest discover -s cloud/crm_performance_001 -p 'test_*.py' -v`

40 тестов PASS: 15 проверок производительности, 18 проверок stage recovery
и 7 существующих проверок политики статусов. В проверках производительности:
отсутствие публикации из callback/job; отсутствие ложного
сообщения об успехе; сохранение правок во время публикации; старый формат
журнала; один worker; сохранение cooldown при перезапуске и перезаписи HTML;
новая правка снимает cooldown; автоматический повтор; скрытие; отсутствие
голодания других карточек при временной ошибке; отклонение иных исходников.

Fixture этого пакета содержит только код worker без CRM-данных, токенов или
секретов. Callback-проверки используют готовые функции из stage recovery.
Сборка от полных проверенных исходников прошла компиляцию; два результата
stage recovery сохранены побайтово. candidate_manifest.json фиксирует SHA
трёх выходных модулей и их исходных зависимостей.
