## Почему старые карточки не запустятся сами после такого перехода

Глобальный autostart слушает только push в main с путём `tasks/launch/AUTO-*.json`. Он требует ровно одно изменение: добавление нового launch-файла, а также run_attempt=1. Удаление HALT и добавление recovery receipt/archive не соответствуют этому триггеру. Все 17 существующих AUTO markers дополнительно просрочены. Политика режима требует `allow_replay_existing_launch_markers=false`; consumed records и nonce reservations запрещают повтор ранее принятой идентичности. Ни одна из этих записей не очищалась и не должна очищаться данным восстановлением.

Maintenance и monitor не извлекают старую очередь публикаций. Watchdog работает по незавершённым production transactions; в текущем снимке таких нет. Плановые GitHub jobs могут появиться позднее: непосредственно перед отдельным утверждённым переходом необходим повторный GET очереди и проверка main, затем существующая сериализация `ua-art-production-writer` и compare-and-swap.

## Границы результата

Отсутствие активных GitHub runs/claims подтверждено только во время чтения. Этот аудит не проверяет внешние процессы PythonAnywhere и ручных писателей вне GitHub.
