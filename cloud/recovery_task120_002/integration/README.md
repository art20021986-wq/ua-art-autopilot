# Подключение маршрута TASK120

Основание: команда владельца **«подключай проверенный маршрут исполнения.»** от 09.09.2026. Она разрешает подключение проверенного маршрута и проверку его работы с сохранением HALT. Команда не разрешает снятие аварийной остановки, публикацию карточек или изменение CRM/сайта.

Предыдущий подготовительный этап сохранён в [PR №80](https://github.com/art20021986-wq/ua-art-autopilot/pull/80). Этот пакет содержит реальное подключение к существующему workflow, а не только локальную модель перехода.

## Что подключается

В существующем `uaart_transaction_watchdog.yml` добавлены отдельные режимы плана, canary и исполнения. Сохранена общая группа записи `ua-art-production-writer`. Прежняя ветка обработки незавершённых транзакций остаётся доступной только по расписанию.

После изменения **единственного** файла регистрации на main автоматически запускается canary. Он проверяет доверенный источник кода, весь runtime, точную остановку TASK120, историю, завершённые транзакции и очередь GitHub. В очередь допускается только фактически наблюдавшийся текущий запуск с совпадающими repository/run/workflow/source/actor. Все пять статусов проверяются с полной пагинацией; данные старше 120 секунд отклоняются.

Canary вправе добавить только `state/recovery_route_receipts/UA-ART-RECOVERY-TASK120-002.json`. Применяется один Git commit с одним parent и один compare-and-swap ожидаемого main. Затем выполняются чтение удалённого результата и проверка сохранности HALT, runtime и управляющих ограничений. Повтор не создаёт новую запись. Путь canary receipt не совпадает с путём запуска, поэтому обратного цикла запусков нет.

Локальная проверка Git сама не называется live PASS. Доказательство рабочего canary требует фактического GitHub run, успешного шага записи, отчёта `remote-readback.json` и успешной последующей проверки. Итоговые ссылки и состояние фиксируются в протоколе подключения.

## Какие файлы рабочего управления меняются

| Путь | Назначение |
|---|---|
| `.github/workflows/uaart_transaction_watchdog.yml` | Проверенный маршрут и ограниченный запуск canary |
| `automation/transaction_watchdog.py` | Читающие проверки и подготовка строго ограниченных данных перехода |
| `automation/control_plane.py` | Проверка новой регистрации с сохранением предыдущего основания автоматического режима |
| `state/AUTOPILOT_RUNTIME_MANIFEST.json` | Хеши проверенной версии runtime |
| `state/EXECUTION_MODE.json` | Привязка к новой регистрации и manifest; остальные правила сохранены |
| `state/runtime_activations/UA-ART-RECOVERY-TASK120-002.json` | Отдельная регистрация с текущей командой владельца и запретом снятия HALT |
| `state/runtime_activations/UA-ART-RECOVERY-TASK120-002.previous-manifest.json` | Точные исходные байты предыдущего manifest |
| `state/runtime_activations/UA-ART-RECOVERY-TASK120-002.previous-mode.json` | Точные исходные байты предыдущего режима |

Из 18 runtime-файлов изменяются только три; остальные 15 остаются прежними. Историческое approval TASK107, его receipt и сам HALT сохраняются байт в байт. У исходных 115 проверенных файлов меняются ровно пять путей: три runtime-файла, mode и manifest. Все остальные 110 сохранены.

Новых секретов, PythonAnywhere credentials, активных workflow-файлов или расширений token scopes не добавляется. Обновлённые правила сохраняют точные списки событий, задач и путей записи, изолированный Python и проверку источника до запуска кода репозитория. Токен GitHub используется только в ограниченных шагах GitHub GET и Git-записи и снимается до запуска Python из репозитория.

## Приёмка

- [registration-validation.json](evidence/registration-validation.json): проверка всех новых привязок; обычный автоматический запуск по-прежнему получает `AUTOMATIC_MODE_HALTED`.
- [registration-test-result.json](evidence/registration-test-result.json), [полный журнал](evidence/registration-tests.log): общий прогон на зафиксированных исходниках.
- [workflow-writer-test-result.json](evidence/workflow-writer-test-result.json): выполнение самих Bash writer-команд против новых временных Git-репозиториев, включая отказ при дрейфе.
- [route-review.md](route-review.md): независимая проверка точной редакции.
- [rollback-plan.json](evidence/rollback-plan.json): возврат пяти изменённых файлов управления к исходным версиям при неуспешном подключении, без удаления истории регистрации.

## Условия снятия HALT

**Подключение маршрута не означает готовность снимать HALT.** Адаптер сейчас явно блокирует `recovery-execute` с `EXTERNAL_WRITER_VERIFICATION_REQUIRED`: отсутствие внешнего исполнителя PythonAnywhere ещё не подтверждено проверенным механизмом. Параметром CLI или полем `true` этот запрет снять нельзя. Поэтому данное подключение не обещает, что одной команды владельца уже достаточно для завершения восстановления.

Для будущего перехода также предусмотрена отдельная команда `СНЯТЬ HALT UA-ART-RECOVERY-TASK120-002 <точный SHA плана>`, поданная подтверждённым владельцем через зарегистрированный маршрут. Проверяется идентификатор владельца, текущий main, хеш плана, неизменяемый canary receipt и свежая очередь. По расписанию либо по push удаление HALT не выполняется.

Трёхфайловая механика удаления HALT и добавления архива/receipt проверяется только в изолированных тестах, где отсутствующее подтверждение внешних исполнителей явно подменяется тестом. Эти тесты не разрешают рабочий переход и не доказывают состояние PythonAnywhere.

Спецификация, один VIN и публикация карточек остаются отдельной работой [PR №79](https://github.com/art20021986-wq/ua-art-autopilot/pull/79). Это подключение не размещает UA-0017/UA-0018 и не закрывает общий Gate B по сайту.
