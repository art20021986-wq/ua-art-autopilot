## Подтверждённые ограничения

- Регистрация имеет отдельное назначение `REGISTER_RECOVERY_ROUTE_ONLY`. Исходное разрешение TASK107 остаётся неизменным; предыдущие mode и manifest сохраняются с исходными SHA. Все прежние флаги режима проверяются на сохранение. Допускается изменение ровно трёх runtime-файлов; остальные 15 остаются прежними.
- До выполнения кода репозитория проверяются точный main-коммит, источник workflow, все 18 runtime-файлов и соответствие содержимого Git-объектам. Загрузка control plane использует проверенный исходный текст, без исполнения кешированного `.pyc`.
- Новые задания не получают секрет PythonAnywhere. Чтение очереди использует только GET; токен убирается до исполнения Python из репозитория. Запись Git ограничена отдельным шагом.
- Проверка очереди требует всех пяти активных статусов, полной пагинации, свежести и наблюдаемого текущего запуска с правильными реквизитами. Проверяются все сохранённые claims, транзакции и автоматические launch-маркеры; чужой активный запуск или незавершённая запись блокируют новый план.
- Canary может добавить только `state/recovery_route_receipts/UA-ART-RECOVERY-TASK120-002.json`. Исходный HALT сохраняется. Прежние задания watchdog выполняются только по расписанию; canary по расписанию зависит от успешного `discover` с результатом `NONE`. Внутри одного запуска он не выполняется вместе с восстановлением незавершённой транзакции.
- Canary использует один коммит с точным ожидаемым родителем и одну запись main через compare-and-swap. Повторной записи, переноса на другой родительский коммит и автоматического пересоздания плана нет. Проверяются точный набор изменённых путей, ответное чтение main, сохранение HALT и runtime/authority-файлов.
- Повторный canary проверяет текущую политику и неизменность ранее созданной квитанции. Изменение с последующим восстановлением или удаление с повторным добавлением квитанции отвергается.
- Локальная проверка Git-коммита сообщает `git_commit_verified`, а не подтверждение рабочей записи. Отдельный `remote-readback.json` создаётся только после успешного ответного чтения удалённого main. Для объявления рабочего canary успешным также нужен завершённый запуск с успешной проверкой принятого коммита.
- `execute` доступен только в контексте отдельного ручного запуска владельца с точным main, SHA плана и отдельной командой. Дополнительно он **безусловно блокируется** проверкой `EXTERNAL_WRITER_VERIFICATION_REQUIRED`: достоверный источник текущего состояния внешних исполнителей ещё не подключён. Флага CLI или переменной окружения для обхода нет.
