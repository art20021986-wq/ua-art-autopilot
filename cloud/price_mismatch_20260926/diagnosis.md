# Цена в CRM ≠ цена на сайте (Safari / Google / TikTok) — диагностика 2026-09-26

Режим: только чтение. Production не менялся. Живой сайт из облачного
контейнера недоступен (egress блокирует www.uaart.com.ua) — вывод сделан
по коду и доказательствам в репозитории.

## Как устроена цена на сайте
1. Цена «зашита» в статический HTML карточки (`/home/Carix/video/UA-XXXX.html`,
   `katalog.html`) в момент публикации. Смена цены в CRM-боте HTML не меняет.
2. 22.09 (GE-PUBLIC-PRICES-20260922, установлено) добавлено: JSON
   `/ua-art-public-prices-v1.json` из `crm.db` (no-store) + код в
   `/video/ua-site-languages.js`, который в браузере подменяет цену на цену из CRM.
3. Страницы подключают скрипт по старому адресу
   `ua-site-languages.js?v=site-ge-002-v1`. Задача смены версии адреса
   (GE-PRICE-CACHE-20260922) упала до production (`STORAGE_PROBE_STALE_OR_FUTURE`),
   HALT, установка не выполнена. `browser_acceptance` так и остался
   `PENDING_CACHE_REFRESH_VERIFICATION`.

## Причина
Safari и встроенные браузеры TikTok/Google держат в кеше старую версию
скрипта (тот же адрес) и/или старую HTML-страницу. Старый скрипт не ходит
за ценой в CRM → показывается старая цена из HTML. Там, где кеш свежий,
видна цена CRM — отсюда «разные цены в разных приложениях».
Дополнительно: превью ссылок, поисковики и пользователи без JS всегда видят
цену из HTML.

## Варианты
A. Довыпустить GE-PRICE-CACHE (сменить `?v=` в 22 страницах). Быстро, пакет готов;
   нужно снять HALT и пересобрать проверку хранилища. Лечит кеш скрипта, но не
   старую цену в самом HTML.
B. Обновлять цену в HTML карточки и каталога при изменении цены в CRM
   (запись через существующий publication fence с бэкапом). Цена верна везде,
   включая превью и Google.
C. Отдавать страницы карточек через WSGI с подстановкой цены из crm.db и
   `Cache-Control: no-cache`. Самый надёжный, но крупнее по объёму.

Рекомендация: A сейчас, затем B.
