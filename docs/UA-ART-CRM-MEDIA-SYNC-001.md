# UA-ART-CRM-MEDIA-SYNC-001 — фото и видео CRM → сайт

Версия 1.0 • 27.09.2026 • Заказчик: Артем, UA ART Company.

Основание: поручение владельца сверить исходники фото и видео CRM с сайтом,
устранить расхождения и их причины, обеспечить правильное добавление,
замену, изменение порядка, скрытие и удаление. Работа разрешена этим
поручением. Повторное общее согласие не требуется; действующие проверки
установки, резервирование и защита транзакций обязательны.

## 1. Результат

CRM определяет состав, порядок, видимость и обложку опубликованных медиа.
Файлы, оставшиеся в папке после изменения CRM, не становятся источником
публичной галереи. Внутренние и скрытые материалы исключаются.

Для каждого оригинала требуется доказанная связь: автомобиль → запись CRM
→ загруженные байты → SHA-256 → публичный оригинал и производные.
Совпадение числа файлов, названий либо ответ HTTP 200 не является
доказательством идентичности.

Под «идентично» для оригинала понимается совпадение SHA-256 и размера.
Миниатюры, обложки и перекодированное видео могут отличаться байтами;
для них обязательны ссылка на исходный хеш и версия преобразования.
Фото, отправленное в Telegram как сжатое изображение, сравнивается с
доступным CRM/Telegram исходником, а не с недоступным оригиналом телефона.

## 2. Охват

Архивные записи учитывать отдельно по действующим правилам проекта.
Цены, статусы, VIN, описания и данные клиентов этим ТЗ не изменять.

## 4. Требования к исправлению

| Операция в CRM | Обязательное поведение сайта |
|---|---|
| Добавление | Только подтверждённый новый файл нужного автомобиля, один раз, в порядке CRM |
| Замена | Новые байты получают новый неизменяемый URL; оригинал и производные одной версии |
| Удаление | Медиа исчезает из галереи, плеера, обложек и публичных списков; старое событие не возвращает его |
| Скрытие | Скрытое исключается из всех представлений; скрытая обложка заменяется первым видимым фото |
| Перестановка | Порядок CRM одинаков в превью и увеличенной галерее; видимая выбранная обложка первая |
| Удаление всех медиа | Пустое состояние без старых фото/видео; явно согласованная нейтральная заглушка |
| Ошибка/прерванная загрузка | Нет публикации частичного файла и ложного успешного статуса; повторяемое состояние ошибки |

Публичное исключение медиа не означает безвозвратное удаление оригинала.
Старые файлы сохраняются в рамках отката. Закрытие доступа к старому
прямому URL скрытого медиа требует отдельной политики доступа: фильтр HTML
сам по себе такого запрета не обеспечивает.

Загрузчик: запись во временный файл → проверка полного файла → вычисление
хеша → атомарное размещение неизменяемого оригинала → подтверждение
готовности в манифесте. Завершённым считать только согласованное состояние.
Не угадывать связь по порядковому имени, размеру или числу файлов.

Ревизия включает упорядоченные фото и видео, скрытие, обложку, идентичности
и готовность загрузок, хеши оригиналов и версию преобразования.
Служебные попытки и время опроса не должны вызывать бесконечную пересборку.
Событие изменения сохраняется надёжно вместе с изменением CRM либо
достигается эквивалентная проверенная гарантия повторного обнаружения.

Публикация использует штатную блокировку и транзакцию. Перед записью
проверяется модель и файлы; после — обычный публичный URL и свежая ревизия
CRM. Старый результат не может заменить более новую версию. События
должны быть идемпотентными; перезапуск не теряет незавершённую работу.

## 5. Скорость, кэш и статусы

Изменение запускает обновление сразу после сохранения. При штатных ресурсах
готовые медиа должны отразиться в обычном открытии страницы за ≤60 секунд;
для нового большого файла отдельно измеряются загрузка и публикация.
Не подтверждать «обновлено», пока файл ещё загружается. Открытая активная
вкладка проверяет ревизию при возврате и не реже одного раза в 60 секунд.

HTML/JSON проверяют актуальность. Изменившиеся байты фото, видео,
миниатюр и постеров не выдаются под прежним неизменяемым URL.
Разовая очистка браузера не считается постоянным исправлением.

CRM различает: сохранено, ожидает загрузки, публикуется, проверено на
сайте, ошибка. Успех — только после содержательной сверки. Временные сбои
повторяются с ограничением частоты; постоянные ошибки остаются видимыми.
Для отказов использовать существующий журнал/интерфейс CRM. Не вводить
новый канал уведомлений без поручения владельца.

После каждой публикации выполняется адресная сверка; периодический
контроль выявляет пропущенные изменения. Полный тяжёлый аудит каждую
минуту запрещён. Частота и лимит ресурсов фиксируются после измерения.
